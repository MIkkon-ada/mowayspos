# 本地 V2 立项流程完善与验收

验收日期：2026-10-12（Asia/Shanghai）。范围：本地 `frontend-v2` 与当前工作区 FastAPI；没有部署生产，也没有使用子代理或提交混合工作区。

## 实际修复

1. 建项明确为“保存项目草稿”，说明下发、负责人完善方案和企业教练审核的先后关系。
2. 新增服务器草稿读写接口，按项目和人员身份隔离；不完整内容可保存，保存不会改变项目状态，也不生成正式任务。支持自动保存、手动保存、保存失败重试和账号／项目隔离的本机恢复缓存。
3. 返回项目时保存未保存修改，刷新时恢复草稿；审核退回后带回原工作计划和退回意见。
4. 方案编辑、完整预览与审核采用一致的重点工作／关键任务结构，标准展示全文；项目概览放在上方，减少对编辑宽度的挤占。
5. 日期改为独立的开始／结束输入，保留历史模糊日期的显示兼容。数据库计划时间字段从 20 扩至 80 字符，完整日期范围不再超出目标 PostgreSQL 字段长度。
6. 按任务 ID 修订；改名保持原 ID；新的同名工作分别保存；修订移除采用软删除，有关联汇报、成果、问题或执行记录的对象不能被移除。
7. 修复项目详情页原来只关闭弹窗的审核通过／退回占位逻辑，实际调用接口并刷新项目状态。退回意见改为页面内输入，兼容不支持原生 `prompt()` 的内置浏览器。
8. 项目列表和详情页加载审核材料失败时展示错误、提供重试并阻止审批，不将接口失败显示成“没有计划”。
