# 会议纪要 AI 分析与草稿保存追踪

> 记录时间：2026-08-03
>
> 追踪对象：会议 `#2`，项目 `#1（AI升级计划）`
>
> 目的：还原本次“口语化会议文本 → AI 分析 → 草稿保存 → V1 历史版本”的实际输入与输出，不把未留存的数据伪造成日志。

## 1. 输入：用户提交的会议原文

输入方式：手动粘贴会议讨论文字。

```text
张总：那我们今天简单过一下项目进展，重点看流程梳理、旧知识库迁移，还有顾问作业场景这几块。

温会林：我这边项目经理流程已经梳理了一版，现在主要是在做细节优化。目标还是8月3日前完成定稿，定稿以后再把里面能结合AI的环节整理出来，后面启动开发。具体哪些环节先做，我还需要跟大家再确认一下。

张总：好的，流程定稿是明确事项，AI环节开发先列入后续计划，不要现在就算完成。

郭熠彬：我这边准备下周用琥崧项目的历史文件测试中转系统调用。现在主要问题是企业微盘连接还不稳定，有时候能读到文件，有时候会超时。这个问题我先排查一下，另外旧的 Teambition 知识库迁移，预计一个月左右完成。

张总：中转系统测试下周开始，企业微盘连接问题需要优先处理。知识库迁移先保留一个月这个计划，但最终截止日期还没有定。

许明良：顾问作业场景我已经整理了一部分，目前一共21个场景。我的计划是8月3日前把场景梳理完，筛选出10个核心场景，然后再做分工和启动开发。现在还缺两位同事帮忙确认场景优先级。

张总：这件事的负责人还是许明良，优先级确认需要谁来负责今天先不指定，放到待确认里面。筛选10个核心场景属于明确工作，启动开发要等场景和分工确认以后再开始。

吴肖：我这周完成了新项目管理平台的版本更新，下周准备组织一次AI升级周会，具体会议时间还没定。平台目前可以正常使用，但是旧数据兼容性还需要再观察一下。

张总：平台更新算已完成，AI升级周会先记录为后续安排，时间待定。旧数据兼容性是当前风险，吴肖先补充一份测试结果，什么时候提交暂时没有明确。

张总：今天结论就这些。已经明确的事项按行动清单推进，没有明确负责人的先不要自动分派。下次会议重点看流程定稿、中转系统测试结果和顾问场景筛选结果。
```

## 2. 输入：前端调用 AI 分析接口

前端调用：`POST /api/meetings/analyze`

本次已知请求字段：

```json
{
  "project_id": 1,
  "mode": "progress",
  "text": "见第 1 节完整原文",
  "member_names": [
    "moways",
    "冯海林",
    "刘万超",
    "吴肖",
    "杨宇帆",
    "郭熠彬",
    "邹奇敏",
    "温会林",
    "许明良"
  ]
}
```

说明：成员名单来自项目 `#1` 当前成员。项目上下文只用于核验负责人身份，不应作为会议事实来源。

## 3. 处理：后端传给模型的分析规则

后端使用“项目推进汇报”模式的提示词，并附带：

- 第 1 节会议原文；
- 项目成员/工作推进上下文；
- 不得臆造负责人、时间、风险和结论的规则；
- 行动项应包含负责人、事项、截止时间、验收标准、原文依据的规则。

**未留存的数据：** 模型的原始 Prompt、模型名称、原始 JSON 回包、前端审核前页面状态均没有持久化。因此无法事后证明模型最初输出了什么，也无法区分“模型生成”与“用户审核页手动编辑”的每个字段来源。

## 6. 本次结果与原文不一致之处

| 字段 | 原文事实 | 本次草稿 | 判定 |
|---|---|---|---|
| 温会林截止时间 | `8月3日前` | `8月3日` | 错误：丢失“前” |
| 许明良截止时间 | `8月3日前` | `8月3日` | 错误：丢失“前” |
| 验收标准 | 原文未明确给出独立验收标准 | 生成了多条具体标准 | 不应直接采信 |
| 待企业教练决策 | 原文没有明确要求企业教练裁定 | 生成 3 条 | 应改为未决/待确认事项 |
| 风险 | 企业微盘连接不稳定、旧数据兼容性待验证 | 写入流程截止/测试计划/平台更新 | 错误字段映射 |
| 成员汇报 | 分析页可能展示 | 保存后无独立字段 | 当前丢失结构化结果 |

## 7. 当前可追溯性结论

本次可追溯：原始转写文本、保存后的摘要、行动项、决策字段、风险字段、保存时间、保存人和 `V1` 快照。
