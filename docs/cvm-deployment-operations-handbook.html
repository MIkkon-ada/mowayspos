00 / BOUNDARY

区分三类操作

镜像发布不会自动部署；应用更新不默认运行迁移；数据库迁移不包含主机网络变更。

操作范围不包含
GHCR 镜像发布构建、扫描并推送固定提交 SHA 对应的应用镜像。CVM 连接、容器重建、数据库操作。
CVM 增量更新替换明确批准的应用组件。清空数据、重建无关容器、主机代理或 DNS 修改。
数据库迁移运行审核后的 schema 迁移并核对 Alembic 版本。自动回退、删除或重建 PostgreSQL。
01 / PREFLIGHT

发布前核对

计划、运行证据和回退材料不全时，不开始变更。

01CHANGE RECORD记录工单、负责人、目标环境与维护窗口

登记审批人、执行人、影响、验证人和停止条件。写明仓库、分支与完整提交 SHA，确认测试或生产目标。不要在手册中记录主机密钥或令牌。

02SOURCE OF TRUTH确认提交内容经过审阅

检查分支、提交差异和工作区状态。不得为获得干净状态而重置或覆盖他人改动。

LOCAL · READ ONLY
git status --short
git rev-parse HEAD
git show --stat --oneline --decorate HEAD
03RELEASE EVIDENCE记录线上版本和应用健康状态

从可信发布记录、容器镜像摘要、健康检查和实际迁移版本取得基线。不要用本地代码推断线上状态。

CVM · INSPECT SERVICES
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml ps
curl --fail --silent --show-error http://127.0.0.1:18100/api/health

仅在目标主机已核验时执行；健康状态未知或版本无法对应时停止。

04BACKUP & ROLLBACK确认备份有效并保留回退版本

核对备份时间、权限、存储位置、恢复可用性；登记变更前镜像 SHA、Compose 文件和关键配置版本。

保留当前版本和至少一个回滚版本。未经恢复演练验证的备份，不能称为可恢复备份。

应用镜像回退与数据库 schema 回退是两回事。迁移可能不可逆，必须另有批准的恢复或向前修复方案。

02 / GHCR

私有镜像发布

选择真实存在的 GitHub Actions 工作流 CLOUD P1B2B-A private GHCR image publish。先做 audit；只有审计通过且获得发布批准后才能 publish。

05WORKFLOW DISPATCH验证 main 分支和完整提交 SHA

只对 main 上完整 40 位 SHA 启动此 workflow_dispatch。audit 构建并扫描两类应用镜像，不登录 GHCR、不推送镜像。

运行失败或状态不明都视作未通过。不要猜分支、短 SHA 或 workflow 输入。

06AUDIT GATE审阅密钥、内容和漏洞扫描

确认 secret scan、可修复 HIGH/CRITICAL 漏洞、镜像内容和 Docker history 检查均通过。只保存脱敏摘要，不上传扫描原始文件。

不得通过关闭扫描、忽略真实密钥或降低安全阈值来获得绿色结果。
07IMMUTABLE RELEASE核对不可变 SHA、远程摘要和私有包状态

发布后检查 backend/frontend 镜像标签均与完整提交 SHA 一致，远程摘要匹配且包可见性为 private。

禁止使用可变的 latest、main 或 production 标签。镜像发布不会部署到 CVM，也不会迁移数据库。
03 / CVM

CVM 增量应用更新

按已批准的 CLOUD CVM incremental application deploy 变更记录执行。现有 GHCR 发布 workflow 本身不会连接 CVM。

08WORKFLOW CONTRACT核实组件选择与迁移开关语义

确认当前部署系统确实提供此 workflow，并审核它的仓库、目标分支、权限和输入契约。验证 component=backend、frontend 或全应用组合对应的重建范围；run_migrations=true 只应启用已批准的数据库变更。

workflow 不存在、参数定义不明或目标与工单不一致时，立即停止；不要猜测默认值、主机或部署行为。
09HOST IDENTITY核实主机身份并安全建立连接

CVM_HOST、CVM_USER、CVM_SSH_KEY、CVM_KNOWN_HOSTS 是凭据管理字段名，不要在文档、脚本输出或仓库中写入其真实内容。必须校验 SSH host key。

LOCAL · VERIFY KNOWN HOSTS
ssh-keygen -F "$CVM_HOST" -f "$CVM_KNOWN_HOSTS"
ssh -o BatchMode=yes -o StrictHostKeyChecking=yes "$CVM_USER@$CVM_HOST" 'printf "host_identity_verified\n"'

由授权人员在受控终端加载密钥，不要放入命令行参数或仓库。

10IMAGE PROVENANCE核对镜像 SHA 与远程摘要

从成功发布记录取得 backend/frontend 的完整 SHA 和远程摘要，逐一核对本次要更新的组件。首次拉取按已审核契约核验摘要，不用浮动标签。

CVM · VERIFY IMAGE REFERENCES
docker image inspect ghcr.io/mikkon-ada/mowayspos-backend:"$RELEASE_SHA" --format '{{index .RepoDigests 0}}'
docker image inspect ghcr.io/mikkon-ada/mowayspos-frontend:"$RELEASE_SHA" --format '{{index .RepoDigests 0}}'
11CONFIGURATION检查 Compose 配置与变更范围

显式使用当前 Moways env 与 Compose 文件。检查服务、镜像 tag、端口和 volume；不要复制包含敏感值的展开配置。

CVM · VALIDATE CONFIGURATION
cd /opt/mowayspos
docker compose --env-file /opt/mowayspos/production.env -f docker-compose.prod.yml config --quiet
docker compose --env-file /opt/mowayspos/production.env -f docker-compose.prod.yml ps

若出现未计划的服务重建、端口公开或数据目录变化，停止并复审。

12SCOPED UPDATE只更新批准的应用组件

本步骤只适用于批准更新 backend 与 frontend 的变更；命令显式排除依赖服务。若只需更新单个组件，应按批准契约收窄命令。

CVM · APPLICATION SERVICES ONLY
docker compose --env-file /opt/mowayspos/production.env -f docker-compose.prod.yml pull backend frontend
docker compose --env-file /opt/mowayspos/production.env -f docker-compose.prod.yml up -d --no-build --no-deps backend frontend
禁止运行 prune、down、删除 volume 或针对其他 Docker 项目的命令。
04 / DATABASE

数据库迁移独立审批

没有迁移批准时，不运行 schema 命令。此流程不提供自动回退，也不能替代备份演练。

13MIGRATION REVIEW审核迁移脚本、head 数量和恢复方案

审阅数据量、锁表预期、执行耗时和迁移差异；确认只有一个 Alembic head，备份或前向修复路径已由数据库负责人批准。

RELEASE ARTIFACT · REVISION GRAPH
cd bowei_ai_dashboard
python -m alembic heads
python -m alembic history --verbose
14PRE-MIGRATION SNAPSHOT读取实际数据库 revision 并记录备份

经授权数据库通道读取实际 revision，记录备份标识、时间和校验结果。不要将生产连接串写入命令历史。

CVM · CURRENT REVISION
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml exec -T postgres sh -ec 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Atc "select version_num from alembic_version"'
15CONTROLLED MIGRATION只在批准窗口内迁移并核对 revision

保持严格错误处理。任何迁移、revision 或表结构检查失败都应阻止应用启动并升级给负责人。

CVM · APPROVAL REQUIRED
set -euo pipefail
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml run --rm --no-deps --pull never backend alembic upgrade head
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml exec -T postgres sh -ec 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Atc "select version_num from alembic_version"'

不得使用 create_all、不得删除数据库、不得清空 PostgreSQL 数据目录、不得未经审批执行 downgrade。

05 / VERIFY & RECOVER

验证、停止与回退

成功以服务健康、业务冒烟和版本记录均通过为准。命令退出码为零不是完整验收。

16HEALTH CHECK确认服务、端口边界和健康接口

确认服务 healthy，frontend 仅绑定批准的 loopback 端口，backend 与 PostgreSQL 不直接公开主机端口。

CVM · POST-DEPLOY SMOKE CHECK
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml ps
curl --fail --silent --show-error http://127.0.0.1:18100/
curl --fail --silent --show-error http://127.0.0.1:18100/api/health
test "$(curl --silent --output /dev/null --write-out '%{http_code}' http://127.0.0.1:18100/api/auth/me)" = "401"

用获批测试账号走只读路径核验；不要用生产数据试写。

17STOP CONDITIONS异常时停止并保留脱敏证据

摘要不符、迁移版本异常、数据库不健康、应用反复重启、端口变化或关键读取失败时停止。由负责人决定后续回退或前向修复。

CVM · LIMITED DIAGNOSTICS
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml ps
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml logs --since=15m --tail=300 backend frontend

日志脱敏后进入受控事件工单。不要上传环境文件、令牌或未经审阅的个人数据。

18APPLICATION ROLLBACK按已批准版本回退应用镜像

由变更负责人批准后，将 env 文件恢复到已记录旧 SHA，复核差异，只更新应用服务并重复健康检查。

CVM · AFTER APPROVED TAG RESTORE
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml config --quiet
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml pull backend frontend
docker compose --env-file /opt/mowayspos/production.env -f /opt/mowayspos/docker-compose.prod.yml up -d --no-build --no-deps backend frontend
应用镜像回退不会自动回退数据库 schema。若迁移后不兼容，按数据库事件方案处理，不要自行 downgrade 或删除数据。
19CLOSEOUT记录变更结果、证据与交接

记录时间、结果 SHA、镜像摘要、迁移 revision、健康检查、冒烟路径、异常与处置人。清理临时资源坚持“先列出，再确认，最后定向删除”；确认没有遗留临时凭据、容器或告警，并登记后续事项责任人。

20RECOVERY DRILL单独安排恢复演练，不在发布现场试错

在隔离环境演练数据库备份恢复和应用前后版本兼容，测量恢复时间与数据核对结果。生产变更时不得首次试验恢复方法。

离线参考不能读取 GitHub、CVM 或生产数据库，也不能替代审批。执行前必须依据当前仓库、工单和现场证据复核命令。勾选只保存在本浏览器 localStorage，不是服务器状态或操作日志。
