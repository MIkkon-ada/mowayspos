# 会议页项目选择方卡设计

## 目标

当用户尚未选定项目时，将会议页原有的项目名称列表改为信息清晰、可点击的项目方卡，使用户能在进入项目之前快速识别项目及其基本信息。

## 页面与布局

- 仅调整 `frontend/src/pages/MeetingPage.tsx` 中 `!effectiveProjectId && !loading` 的项目选择状态；已选项目后的会议列表与功能不改变。
- 延续现有浅蓝灰页面背景、白色圆角容器和蓝灰文字系统。
- 页面保留标题“请选择要查看的项目”、说明文字和底部导航提示。
- 每个项目渲染为一张近似正方形的可点击卡片；项目较多时卡片以响应式网格换行，在小屏幕回退为单列。

## 卡片信息层级

1. 顶部：项目图标、项目名称与状态标签。
2. 中部：两列网格展示项目周期、项目经理、项目成员数和当前进度。缺少后端数据时，以“暂未设置”或“—”保持布局稳定；不新增接口或数据模型。
3. 底部：细进度条和“进入项目 →”入口提示。
4. 整张卡片保持现有按钮行为：点击后通过 `projectId` 查询参数切换当前项目。

## 数据边界

- 使用当前 `projects` 列表中已有的字段；项目名称与项目编码继续可用。
- 本轮不修改项目 API、数据库、权限逻辑或会议创建流程。
- 仅在已存在对应字段时显示真实的经理、周期、成员与进度；否则以一致的占位信息显示，避免编造业务数据。

## 交互与可访问性

- 卡片仍为原生 `button`，保留键盘操作能力。
- Hover 与 focus 状态采用浅蓝边框、背景和阴影强化，避免纯色大面积填充。
- 状态信息仅做展示，不影响项目选择。

## 验证

- 新增前端结构测试，确认会议页包含项目方卡、信息标签、进度条与原有项目切换行为。
- 执行该测试以及前端既有测试命令，确认无回归。
