# 工作推进表回收站入口调整设计

## 背景

工作推进表当前把“在办”和“回收站”作为同级切换项放在主操作区。
工作推进表默认展示的本来就是未删除的有效工作，因此“在办”入口没有提供额外
筛选价值；回收站属于低频、受权限控制的误删恢复能力，与日常工作视图同级会
放大其视觉权重。

本次调整只改变入口层级和页面状态表达，不删除回收站，不改变软删除、恢复、
审计或权限机制。

## 目标

1. 工作推进表默认直接展示未删除的有效工作。
2. 移除“在办 / 回收站”同级切换。
3. 将“回收站”放入页面右上角现有“操作”菜单。
4. 保留负责人和技术管理员的全部恢复能力。
5. 进入回收站后提供清晰的页面身份和返回路径。

## 非目标

- 不建设项目管理中的“数据与回收站”模块。
- 不增加永久删除。
- 不修改数据库结构、软删除字段或 Alembic 迁移。
- 不修改后端删除、恢复、权限和审计接口。
- 不改变“已完成”与“已删除”的业务语义。

## 页面与交互

### 正常工作推进表

- 页面默认请求未删除记录。
- 不再显示“在办”按钮。
- “操作”菜单保留现有“导出表格”和按权限显示的“从大纲导入”。
- 当用户是当前项目负责人或技术管理员时，“操作”菜单增加“回收站”。
- 普通成员、统筹和其他无回收站权限的角色不显示该入口。

### 进入回收站

选择“操作 → 回收站”后：

1. 清除当前重点工作、关键任务和详情面板选择。
2. 收起已展开的关键任务。
3. 清空搜索、状态和负责人筛选。
4. 切换为请求当前项目的软删除记录。
5. 页面工作区明确显示“回收站”。
6. 在工具区显示“返回工作推进表”按钮。

回收站继续使用当前页面和现有 `showDeleted` 状态，不增加新的路由或后端模块。

### 返回工作推进表

选择“返回工作推进表”后：

1. 清除回收站中的当前选择和展开状态。
2. 将 `showDeleted` 恢复为 `false`。
3. 重新请求当前项目未删除的有效工作。
4. 保持当前项目上下文不变。

## 数据与权限

前端继续调用现有任务和关键任务接口，并通过删除态参数区分有效记录与软删除
记录。后端仍是权限与数据完整性的最终边界：

- 重点工作删除时，同批关键任务一起软删除。
- 恢复重点工作时，只恢复同一删除批次随父项删除的关键任务。
- 单独删除的关键任务可以单独恢复。
- 删除和恢复继续写入操作日志。
- 项目归档后继续禁止业务写入和恢复。
- 回收站访问继续限制为项目负责人或技术管理员。

前端权限判断只控制入口可见性，不能替代后端权限校验。

## 错误处理

- 回收站请求返回 `403` 时，切回正常工作推进表并提示用户无回收站权限。
- 请求失败时不伪造空回收站；保留现有错误提示并允许用户返回。
- 恢复失败时保留当前回收站列表和选择，避免用户误以为已经恢复。
- 项目上下文缺失时不请求全局回收站，沿用当前项目上下文必填提示。

## 测试

前端回归测试至少覆盖：

1. 主工具区不再出现“在办 / 回收站”同级切换。
2. 有权限时“操作”菜单包含“回收站”。
3. 无权限时菜单不显示“回收站”。
4. 进入回收站会清除筛选、选择和展开状态。
5. 回收站显示明确标题和“返回工作推进表”操作。
6. 返回后重新加载未删除记录。
7. `403` 会退出回收站并显示权限提示。
8. 现有重点工作和关键任务恢复调用保持不变。

完成后运行全量前端测试和生产构建，并通过本地前后端实际验证进入、返回及恢复
页面状态。

## 后续演进

未来如建设项目级数据治理中心，可以在项目管理中增加第二个“数据与回收站”
入口，并复用同一页面能力和后端接口。该长期入口不属于本次实施范围。
