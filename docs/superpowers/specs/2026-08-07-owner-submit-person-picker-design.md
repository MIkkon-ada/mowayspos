# 立项提交人员选择设计

## 目标

将“填写立项信息”工作台中每条关键任务的负责人和协助人改为全系统人员选择器，避免手工输入姓名；选择尚未加入项目的人员时，提交立项信息会自动将其加入项目，角色为“协同成员”。

## 交互与数据

- 负责人为单选，必填；协助人为多选，可不选。
- 两个选择器均加载全系统的有效人员，并显示姓名与部门。
- 前端草稿保存所选人员的 ID；请求同时携带兼容现有展示的姓名字段和新增的人员 ID 字段。
- 负责人和协助人重复选择时，协助人侧不重复保存该人员。
- 人员列表加载失败时显示错误并阻止提交，防止保存任意手填姓名。

## 提交规则

- `owner-submit` 在同一数据库事务内校验每个提交的人员 ID 均存在且启用。
- 对负责人及所有协助人：若该人员尚无当前项目的任意成员角色，则创建一条 `project_members` 记录，角色为 `member`（协同成员）；已是项目成员的不重复创建。
- 关键任务仍按姓名快照写入现有的 `assignee` 与 `helper` 字段，保证现有审核、展示和后续任务创建流程兼容。
- 任一人员 ID 无效或已禁用时，整个请求失败，不写项目资料、任务草稿或成员关系。

## 边界与测试

- 仅调整立项提交工作台；项目成员管理页面和其他人员选择器不改变。
- 后端测试覆盖：自动加入单个负责人、多个协助人去重、已是成员不重复写入、无效人员 ID 的原子失败。
- 前端结构测试覆盖：负责人单选、协助人多选、提交携带人员 ID，且不再使用自由文本输入。
