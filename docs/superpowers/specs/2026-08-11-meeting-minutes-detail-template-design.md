# 会议纪要详情模板设计

## 目标

将会议详情页改为可复用的周例会纪要模板。页面不绑定某一次会议的主题、人员或待办数量，只渲染会议数据中的对应字段。

## 信息架构

顶部栏和左侧导航保持现状。详情页包含会议标题、状态、类型和一行基本信息。页签固定为：会议纪要、本周待办、上周追踪、相关资料。

默认的“会议纪要”页签只展示：会议议程、会议小结与决议、整理人与抄送。会议小结按“结论式小标题 + 要点”组织；不再显示通用摘要、行动清单或右侧信息卡。

“本周待办”页签使用六列：编号、会议安排事项、负责人、追踪人、完成时限、来源/备注。“上周追踪”页签使用五列：编号、上周事项、负责人、状态、本周进展/说明。当前后端没有结构化字段时显示空状态，不伪造数据。

## 数据适配

现有 `summary` 用作决议正文的兜底文本；`decision_items_json` 解析为决议条目；`task_list_json` 解析为本周待办的事项文本。结构化待办与追踪字段留给后续生成/编辑流程写入，不兼容已删除的旧会议数据。

## 验收

- 默认页签无待办表格、无右侧信息卡、无“行动清单”。
- 默认页签保留“会议议程”“会议小结与决议”及整理/抄送页脚。
- 本周待办和上周追踪均为独立页签，并分别使用六列和五列标题。
- 空数据保持明确空状态；详情路由仍为独立页面。
