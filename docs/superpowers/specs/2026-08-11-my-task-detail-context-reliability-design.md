# 我的任务详情：项目上下文可靠性设计

## 目标

确保用户从“我的任务”打开一条已关联项目的任务时，详情页始终显示与列表一致的项目和重点工作。详情请求失败时，页面必须显示真实的可理解错误，而不是错误地显示“未关联项目”。

## 现状与根因

列表通过带 `project_id` 的任务列表接口获得父项目、重点工作和子任务标识。详情页随后仅按子任务标识调用 `/api/subtasks/{id}/detail`；一旦该请求失败，前端丢弃 HTTP 错误详情并以空数据渲染面包屑，触发“未关联项目 / 未关联重点工作”的兜底文案。

因此该文案描述的是前端未取得详情数据，不是任务真实的关联状态。

## 方案

1. 从列表跳转详情时，通过路由状态携带已验证的项目 ID、项目名称和重点工作名称；URL 中继续保留 `projectId`，以支持刷新和提交汇报跳转。
2. 详情页在首次请求期间使用路由状态中的上下文显示面包屑。请求成功后，以后端详情返回的父任务信息为准；页面刷新或直接访问时没有路由状态，才使用详情返回值或中性的“正在读取任务归属”。
3. 详情请求失败时，识别 `ApiError` 的状态码与服务端消息，显示“无权查看此任务”“任务不存在或已删除”或“任务详情服务异常”，并提供重试和返回列表。失败状态绝不显示“未关联项目”。
4. 详情 API 接受可选的 `project_id` 查询参数。若该任务实际所属项目与参数不一致，返回 404，避免跨项目上下文或陈旧链接展示错误数据；若一致，返回既有详情和完整父任务链。
5. 补充后端 API 测试，覆盖关联任务详情返回项目链、项目参数不匹配、无权限访问。补充前端结构/视图模型测试，覆盖路由上下文、错误文案与失败时不使用“未关联”兜底。

## 边界

- 不变更项目成员权限规则，仍由后端 `require_project_access` 决定。
- 不补造或迁移缺失的任务关联数据。
- 不修改任务列表筛选、分页或工作汇报的业务规则。

## 验收标准

- 列表显示“AI升级计划 / 某重点工作”的任务，点击详情后显示同一项目链。
- 请求详情时，面包屑不会闪现“未关联项目”。
- 接口返回 403、404、500 时，用户看到准确失败原因和重试入口，不看到“未关联项目”。
- 传入错误 `project_id` 时，详情接口返回 404，且不会泄露其他项目的任务详情。
- 前后端相关测试与前端构建通过。
