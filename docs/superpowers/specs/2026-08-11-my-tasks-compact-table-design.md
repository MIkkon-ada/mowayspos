# 我的任务：紧凑任务表格设计

## 目标

修正“我的任务”页面在任务较少时出现的大面积无效留白，并让筛选、表格、分页和行操作在同一视觉节奏中工作。保留现有查询、筛选、分页、详情跳转、工作推进跳转和工作汇报跳转能力，不改变后端接口、路由或任务状态口径。

## 范围

仅调整以下前端文件及其测试：

- `frontend/src/features/my-tasks/MyTasksTable.tsx`
- `frontend/src/features/my-tasks/myTasks.css`
- 与上述结构或交互直接相关的既有前端测试

不修改 `MyTasksPage` 的数据加载、筛选状态、路由参数或后端代码。

## 交互与布局

1. 页面头部保持紧凑：标题栏高 56px，刷新按钮与标题基线对齐；筛选栏高 48px。
2. 列表卡片由表头、当前页数据行和分页自然撑高，不得以 `flex`、`min-height` 或固定高度占满剩余视口。单条任务时，分页直接位于该行下方。
3. 桌面端保留七列：序号、关键任务、所属项目/重点工作、计划时间、状态、当前进展、操作。行高约 76px；文本继续使用合理截断和两行摘要，避免把列挤窄。
4. “查看详情”是行内主操作；更多按钮紧邻其右侧，并保持触发区不小于 32px。
5. 更多菜单用独立浮层渲染，默认向下贴齐按钮右边缘；当视口底部空间不足时改为向上展开。打开菜单不得改变表格或卡片高度，菜单不得被卡片裁切。
6. 分页位于卡片底部，左右分别放置页大小/总数与翻页控制。只有一页时保留其紧凑高度，不产生空白占位。
7. 小屏维持横向滚动，筛选控件按既有断点换行；不以缩小文字或隐藏字段换取宽度。

## 实现边界

- 继续使用现有 `MyTaskRow`、回调函数和分页计算。
- 将原生 `details` 菜单替换为受控的可定位菜单状态；点击菜单操作、行外区域或按 Escape 后关闭菜单。
- 处理行点击与菜单事件隔离，确保点击菜单不会触发详情页跳转。
- 不引入第三方组件库。

## 验收标准

- 一条任务时，列表卡片底部无明显空白区域，分页紧随任务行。
- 菜单展开不改变列表高度；在接近页面底部的行上可以向上显示且完整可点击。
- 现有七个表格列及三个行操作（详情、查看工作推进、提交工作汇报）仍可用。
- 项目、状态、搜索和分页行为不变。
- 前端构建通过，现有“我的任务”结构测试通过；新增测试覆盖菜单的受控开关与关闭行为。
