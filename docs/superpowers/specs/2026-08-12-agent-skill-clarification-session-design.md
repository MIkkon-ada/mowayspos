# Agent Skill 阻断式澄清会话设计

## 目标

让项目内任意记录员在 WorkBuddy 中运行会议 Skill 时，遇到关键事实不明确即暂停，以单选、多选或“其他”填空的题目向记录员提问。全部必答题确认前，不生成会议纪要草稿、Word 或 Excel。

## 适用范围

- 标准 Word 会议纪要已通过严格校验时：原样结构化保存，不进入本机制。
- 非标准 Word、TXT、粘贴原文、音频转写：由会议编排 Agent 选择通用会议纪要 Skill 或专用周例会 Skill。
- 首期接入：`weekly-meeting-minutes`（验收与回款周例会）。
- 后续 Skill 可复用同一机制，不复制前端或运行状态机。

## 分层与边界

### 编排 Agent（通用层）

负责冻结输入材料、选择 Skill、创建运行、保存问题与回答、暂停和续跑、访问控制、审计，以及最终结果的保存门禁。

### Skill（业务层）

只声明自己的适用条件、需要核验的参考资料、问题规则、候选项来源和结构化输出。Skill 可以请求澄清，但不能自行生成前端交互，也不能绕过未回答的必答问题。

### 确定性工具（工具层）

Word/TXT 读取、上期纪要提取、Excel 明细查询、专名匹配、Word/Excel 输出均由服务或脚本执行；模型只做受证据约束的抽取、归类和候选排序。

## 运行状态

`created` → `preflighting` → `waiting_for_answers`（存在阻断问题时）→ `running` → `ready_for_review` → `saved`

若预检不存在阻断问题，状态直接从 `preflighting` 进入 `running`。通过严格校验的标准 Word 不创建 Skill Run，也不进入本状态机。

- `preflighting`：只做材料完整性检查、确定性事实核验、候选项构建与澄清题生成；绝不调用正式纪要抽取/生成，也不写入任何草稿内容。
- `waiting_for_answers`：运行被阻断；禁止生成草稿、正式 Word 和 Excel。
- `running`：仅在所有阻断问题被明确处置后进入；将冻结材料、已确认事实与 Skill 规则交给正式抽取/生成器，产生待确认的纪要结果。
- `failed`：保留错误和冻结快照；允许重试并生成一个新的运行。
- `cancelled`：记录员主动结束；不产生会议纪要。

## 澄清题模型

每个问题属于同一次 Skill 运行，包含：

- `code`：同一 Skill 内稳定的问题代码，例如 `project_reference_ambiguous`。
- `question_kind`：问题类别，例如 `missing_material`、`fact_ambiguity`、`reference_conflict`、`field_completion`。
- `blocking`：是否阻断本次运行；只有 `blocking=true` 的未处置问题会阻止进入 `running`。
- `question`：给记录员看的问题。
- `evidence`：原文片段、来源及位置。
- `options`：候选值、展示标签和候选依据。
- `answer_mode`：`single_choice`、`multiple_choice`、`free_text`。
- `allow_other`：是否允许手填其他答案。
- `allow_omit`：是否允许“不写入纪要”。
- `required`：该题是否必须被记录员明确处置后，运行才能继续；它不表示必须填写一个业务值。`required=true` 与 `allow_omit=true` 可以同时成立：记录员必须回答，但可明确选择“不写入纪要”。
- `answer`、`answered_by`、`answered_at`：记录员确认的结果与审计信息。

题目必须由 Skill 提供结构化证据与候选依据。每条证据至少含 `source_type`、`source_id` 和 `locator`；存在可引用的原文时保存 `quote`。`locator` 必须能定位到转写段落/时间段、Word 段落或表格单元格、Excel sheet 与行、或上期纪要事项编号。无法给出可靠候选时，只提供手填和（若允许）不写入纪要，不能把模型猜测伪装成选项。

`missing_material` 不套用普通问答的 `answer_mode`：它是阻断型预检项，展示所缺材料及“补充文件”操作。记录员补充材料后，系统创建新的输入快照版本并从 `preflighting` 重新执行；只有材料检查通过后，才生成后续事实澄清题。

运行门禁以 `blocking` 为唯一依据。首期规定 `blocking=true` 的题必须同时 `required=true`；`required=false` 的题不得作为运行阻断条件。`required` 只描述记录员是否必须明确处置该题，不能单独改变状态机。

记录员补充材料后，在同一 Skill Run 下创建新的输入快照版本并保留旧快照；新快照冻结后重新进入 `preflighting`。后续生成只使用当前有效快照版本，因此可追溯每一次预检当时具备和缺失的材料。

## 已确认事实

记录员回答、参考表唯一匹配结果和可复现规则推导结果，都先写入结构化 `ResolvedFact`，再进入 `running`。每条事实包含规范字段、机器值（例如 `project_id`）、展示值、来源类型、关联证据和答案版本。正式生成器只消费这些结构化事实，不重新解释记录员的自然语言答案，也不把候选文本再次交给模型猜测。

## 权限

- 项目内任意成员均可创建会议 Skill 运行，并作为记录员回答该运行的问题。
- 项目负责人、企业教练可查看和补答；不作为必经审批人。
- 回答、改答和续跑均写入审计日志；答案以追加式 `answer_revision` 保存，不覆盖旧值。每次续跑冻结所使用的答案版本集合；最新有效答案在同一次运行中优先于模型推断。

## 周例会 Skill 预检

`weekly-meeting-minutes` 预检依次检查：

1. 是否收到会议转写或可提取文字的文档；
2. 是否明确选择“验收/回款周例会”类型；
3. 是否提供最新验收/回款明细表和上期纪要；
4. 项目、客户、项目编号、金额是否能唯一匹配；
5. 上期待办是否有可确认的状态、承接关系、负责人和完成时限。

缺少必需材料的问题先出现；材料完整后再出现事实澄清问题。回答后由同一个冻结输入和答案集重新执行，不把未验证的项目上下文当会议事实。

## 页面流程

新建会议弹窗增加“Skill 预检”阶段：

1. 记录员上传/粘贴材料并选会议类型；
2. 点击“开始预检”；
3. 若标准 Word 通过，直接进入原样确认页；
4. 若 Skill 需要澄清，进入全页“确认信息”步骤，顶部显示进度；
5. 每题显示原文证据、候选选项及其来源，可选择“其他”或“不写入”；
6. 所有必答题完成后，按钮从“继续回答”变为“生成会议纪要”；
7. Agent 续跑并进入已有的会议纪要确认页。

## 可靠性约束

- 一个运行只能由服务端状态转换；前端不能跳过 `waiting_for_answers`。
- 服务端对草稿、正式 Word、Excel 和保存接口执行同一生成门禁：只要仍有未明确处置的阻断问题，直接调用这些接口也必须被拒绝。
- 提交答案使用幂等键，防止重复点击造成多次续跑。
- 续跑使用冻结的文档文字、参考文件快照、Skill 版本、模型与回答集。
- 回答改动后废弃旧的待生成结果，重新执行；不混用旧结果。
- 所有最终字段要保存其来源：原文、参考表、记录员回答或规则推导。

## 非目标

- 本期不改标准 Word 的原样保留流程。
- 本期不支持 PDF。
- 本期不要求每个会议类型都有专用 Skill；没有专用 Skill 时仍可走通用会议纪要 Agent。
