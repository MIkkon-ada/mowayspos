# AI能力配置升级设计

## 目标

将系统当前分散在 JSON 文件、环境变量和业务模块中的 AI 配置，升级为由数据库驱动的 AI 能力中心。管理员可通过管理界面维护模型、凭证和能力策略；业务模块通过稳定的能力键调用 AI，而不再自行选择 Provider 或拼装客户端。

首期完成通用能力中心，并迁移当前已经接入的 LLM 与 ASR 能力。设计必须允许后续增加任意新能力，而不修改模型管理底座。

## 范围

### 首期纳入

首期注册并迁移以下四个能力域及其细分场景：

| 能力域 | 能力键 | 当前场景 |
| --- | --- | --- |
| 会议分析 | `meeting.analysis` | 启动会解析、会议纪要、任务卡生成、进展复盘、草稿审核 |
| 任务提取 | `task.extraction` | 工作汇报结构化、任务提取、项目归属判断、成果/风险/下一步提取 |
| 项目初始化分析 | `project.init.analysis` | 上传材料解析、目标/重点工作/关键任务建议、人员匹配 |
| 语音转写 | `speech.realtime` | 实时语音转写、音频文件转写、转写上下文增强 |

能力键是稳定的、可扩展的业务标识。后续可直接增加如 `contract.review`、`risk.forecast`、`report.weekly`、`knowledge.qa` 或 `vision.recognition` 等能力键，并为其配置模型与策略，不改动模型目录和凭证边界。

### 首期不纳入

- RAG、Embedding、Rerank、VLM、MCP 工具的实际接入；数据结构保留对新模型类型的扩展能力。
- 自动按成本、质量或可用性动态选型；首期使用管理员显式配置的主模型与有序备用模型。
- 项目级、用户级或租户级策略覆盖；首期只支持全局策略，避免在没有明确授权模型前引入复杂权限矩阵。
- 外部密钥服务集成；首期在应用数据库内进行加密存储，并以部署环境提供加密主密钥。

## 设计原则

1. **模型、密钥、能力策略分离。** 模型定义不含明文密钥；密钥不在一般模型读接口中返回；业务能力不直接依赖 Provider 名称。
2. **数据库是运行时唯一主源。** 日常管理经 API 写入数据库，应用调用只读取数据库的有效配置。
3. **声明式配置仅用于部署预置。** 环境变量只负责数据库连接、加密主密钥和可选的受控预置导入，不能覆盖管理员已启用的能力策略。
4. **显式优先、可追溯、可回退。** 每次调用记录实际模型和策略版本；模型停用、策略变更与迁移均可审计；失败只按已配置的备用顺序切换。
5. **不暴露机密。** API 与前端只能获得 `configured` 状态，写入、测试和清除密钥使用独立接口；日志中不得出现密钥、Authorization 头或完整上游异常正文。

## 数据模型

### `ai_models`

模型目录。每一行代表一个可被能力策略引用的模型端点，而不是一个业务场景。

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定主键 |
| `code` | 全局唯一、不可变的模型代码，例如 `deepseek-chat-primary` |
| `display_name` | 管理界面展示名称 |
| `provider` | Provider 适配器标识，例如 `deepseek`、`dashscope`、`anthropic` |
| `model_name` | 上游模型名 |
| `model_type` | `chat`、`asr`；预留未来类型 |
| `base_url` | 非密钥上游地址 |
| `config_json` | Provider 非敏感可扩展参数，例如超时、ASR 模型或区域 |
| `enabled` | 是否允许被新调用选中 |
| `source` | `migrated`、`builtin` 或 `custom` |
| `revision` | 每次有效配置修改递增 |

`code`、`provider`、`model_name` 和 `model_type` 一经存在调用记录不得被原地变更；管理员须新建模型或停用旧模型，保证历史记录可解释。

### `ai_model_credentials`

每个模型至多一条凭证记录，保存加密后的 API Key、可选 App Secret 和密钥版本。该表不经普通模型详情接口返回，业务查询只在调用时由服务端解密。删除或清空凭证后，关联模型不再可用。

加密使用部署环境提供的专用主密钥，例如 `AI_CONFIG_ENCRYPTION_KEY`。应用未配置该主密钥时，生产环境拒绝启动 AI 能力中心；开发环境允许使用明确标识的临时测试密钥，禁止无加密明文降级。

### `ai_capability_policies`

能力路由策略。每个 `capability_key` 在首期全局范围内只有一个有效策略。

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定主键 |
| `capability_key` | 业务能力键，例如 `meeting.analysis` |
| `primary_model_id` | 必须存在且已启用的主模型 |
| `fallback_model_ids_json` | 有序备用模型 ID 数组，不得重复主模型 |
| `timeout_seconds` | 单次模型调用超时 |
| `max_attempts` | 最大尝试次数，包含主模型 |
| `policy_version` | 每次策略改变递增 |
| `enabled` | 是否允许业务调用该能力 |

策略与模型类型必须匹配：前三个能力域仅可绑定 `chat` 模型，`speech.realtime` 仅可绑定 `asr` 模型。

### `ai_invocation_logs`

调用审计表，记录能力键、策略版本、模型 ID 与模型版本、调用状态、是否发生备用切换、耗时、可脱敏的错误分类、关联业务资源标识和操作者。该表不保存提示词全文、音频原文、模型完整输出或密钥。

## 服务边界与调用流程

新增 `AIService` 作为唯一运行时入口：

```text
业务模块
  -> AIService.invoke(capability_key, request, context)
  -> CapabilityPolicyResolver
  -> 按策略主模型、备用模型顺序调用 ProviderAdapter
  -> 返回标准化结果或结构化 AI 调用错误
  -> 写入 ai_invocation_logs
```

`ProviderAdapter` 负责 Provider 特定的 SDK/HTTP 调用；`chat` 与 `asr` 分别有独立的请求和结果类型。业务模块保留自身 Prompt、输入裁剪和结果校验职责，但不再读取模型配置、选择 Provider 或持有 API Key。

备用切换仅在连接、限流、超时和上游 5xx 等可重试错误时发生；输入校验失败、输出解析失败、业务结构校验失败及权限错误不切换模型，直接返回可诊断错误，避免重复消耗和隐藏质量问题。

## 管理接口与权限

仅技术管理员可执行以下操作：

- 创建、更新、停用和查看模型目录；
- 单独写入、替换、测试和清除模型凭证；
- 创建、更新、启用、停用和查看能力策略；
- 查看调用日志和配置迁移报告。

模型读接口返回 `credential_configured: boolean`，不会返回密文或明文。能力策略列表返回所引用模型的展示信息与可用状态。保存策略时服务端验证模型类型、启用状态、凭证状态、备用顺序和重复引用；保存模型地址时复用现有 SSRF 防护规则。

## 迁移与兼容

现有 `llm_configs.json` 是本次迁移的输入源，而非新架构的长期运行时配置源。

1. 数据库迁移创建四张表及唯一约束、索引。
2. 启动一个可重复执行的迁移服务：读取旧 JSON，按已知 Provider 创建或更新 `migrated` 模型，导入可用凭证，并建立四个首期能力策略。
3. 迁移服务产生结构化报告：每个 Provider、模型、凭证和策略的结果、跳过原因或错误，不记录原始密钥。
4. 导入验证通过后，启用数据库主源；旧 JSON 仅保留只读回滚数据，不参与普通调用。
5. 提供一次性受控回退开关，仅在紧急故障时允许旧解析器读取旧文件；回退事件必须记录审计日志并告警。稳定发布期结束后移除回退开关、文件挂载、旧 JSON API 和旧解析函数。

迁移不得覆盖管理员已经修改过的 `custom` 模型或策略。重复执行只更新仍标记为 `migrated` 且未被管理员接管的记录。

## 错误处理与可用性

- 没有有效策略、策略已停用、主模型不可用且无可用备用模型时，返回稳定的“能力未配置”错误码，不再静默选择 Provider。
- 对每次可重试失败按有序备用模型切换，且不会在同一调用中重复尝试同一模型。
- 模型或凭证更新后不依赖进程重启；下一次调用读取最新有效配置。
- 凭证测试使用临时输入优先、已保存凭证回退的规则，测试结果不写入调用审计表。
- 历史业务结果继续保留已有的 `provider` / `model_name` 字段；新调用额外记录可关联的调用日志 ID，迁移不篡改历史数据。

## 验收标准

1. 技术管理员可管理 `chat` 与 `asr` 模型、独立更新密钥、配置四个能力域策略；普通用户无法访问上述接口。
2. 会议、任务提取、项目初始化和转写均经 `AIService` 调用，不包含 `_pick_provider`、`resolve_provider` 或直接读取 `llm_configs.json` 的运行时路径。
3. 主模型发生可重试故障时按策略切至备用模型；不可重试的输入/输出错误不会切换。
4. API、前端、应用日志和调用审计记录均不泄露密钥；生产环境没有加密主密钥时拒绝启用新能力中心。
5. 旧 JSON 可被幂等导入，并可在受控回退下恢复旧路径；迁移后常规调用只读数据库。
6. 每次调用均可追溯能力键、策略版本、实际模型、尝试次数、结果和耗时。

## 验证策略

单元测试覆盖模型和策略校验、凭证加解密、路由顺序、可重试判断、审计脱敏与迁移幂等性。接口测试覆盖权限、脱敏响应、模型与策略 CRUD。服务测试用伪 ProviderAdapter 覆盖四个能力域、主模型成功、备用成功、全部失败和不可重试失败。前端测试验证管理员页面不渲染密钥、策略只能选择类型匹配的模型。部署测试验证加密主密钥、数据库迁移和弃用 JSON 挂载的演进路径。
