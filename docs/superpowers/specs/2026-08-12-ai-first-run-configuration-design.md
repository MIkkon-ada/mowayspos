# AI 模型管理页面设计

## 目标

将当前 AI 配置页重构为单纯的“模型管理”页面。管理员在这里完成模型的新增、查看、编辑、连接测试、启用和停用；会议纪要、任务提取、项目初始化、语音转写等业务功能在各自页面按需选择已配置模型，不在模型管理页绑定业务能力。

设计参考 WeKnora 当前的模型管理前端：模型类型标签、模型卡片网格、添加模型卡片、右侧配置抽屉，以及抽屉底部并列的测试连接和保存操作。

参考来源：

- `Tencent/WeKnora/frontend/src/views/settings/ModelSettings.vue`
- `Tencent/WeKnora/frontend/src/components/ModelEditorDialog.vue`
- [WeKnora 模型管理 API](https://github.com/Tencent/WeKnora/blob/main/docs/api/model.md)

## 范围

### 本次包含

- 模型管理主页面。
- “全部 / 对话模型 / 语音模型”三个分类。
- 模型卡片列表和添加模型卡片。
- 新增模型右侧抽屉。
- 编辑模型右侧抽屉。
- API Key 独立加密保存、连接测试、启用和停用。
- 加载、空状态、错误和重试状态。

### 本次不包含

- 会议纪要分析、任务提取、项目初始化分析、语音实时转写的模型绑定。
- 业务能力策略配置。
- Embedding、Rerank、VLLM 等当前系统尚未支持的模型类型。
- 新增数据库表或迁移。

## 信息架构

### 模型管理主页面

页面标题为“模型管理”，副标题为“统一配置系统中可使用的 AI 模型”。顶部右侧保留“模型调试”入口，用于对已保存且已配置凭证的模型执行连接测试。

标题下方显示三个标签：

- 全部（数量）
- 对话模型（数量）
- 语音模型（数量）

标签只筛选模型卡片，不改变配置表单结构。默认选中“全部”。

### 模型卡片

每个模型显示：

- 模型类型图标。
- 显示名称；若未填写显示名称，则显示模型名称。
- 服务商和实际模型名称。
- 状态：已配置、缺少 API Key、已停用。
- 更多操作：编辑、测试连接、启用或停用。

卡片本身可点击进入编辑抽屉。主页面最后一张卡片为虚线样式的“添加模型”，点击后打开新增抽屉。

### 添加与编辑抽屉

抽屉从页面右侧打开，宽度约 480px。主页面保留在背景中并加半透明遮罩。抽屉包含两个配置分区。

#### 模型类型

- 对话模型
- 语音模型

新增时可选择；编辑时保持当前类型，不在本次设计中支持跨类型修改。

#### 接入配置

- 服务商：必填，下拉选择。
- 模型名称：必填，对应模型服务商的真实模型 ID，如 `deepseek-chat`。
- 显示名称：可选，仅用于页面展示。
- Base URL：必填；选择服务商后预填常用官方地址，仍允许修改。
- API Key：新增时填写；编辑时仅显示“已配置”状态和“替换密钥”操作，绝不回显已保存密钥。

抽屉底部固定显示：

- 左侧“测试连接”。
- 右侧“取消”和“保存”。

“测试连接”与“保存”相互独立。管理员可先测试再保存，也可直接保存；保存不强制要求测试成功。

## 服务商体验

第一版提供当前后端实际支持并已适配的服务商选项，例如 DeepSeek、阿里云 DashScope、智谱 GLM、Anthropic 和自定义 OpenAI 兼容接口。选择服务商时自动填充默认 Base URL，但不自动猜测模型名称或 API Key。

前端不得暴露 `code`、`display_name`、`provider`、`model_name` 等内部字段名。模型 `code` 由前端根据服务商和模型名称稳定生成，后端继续以现有字段存储。

## 业务功能选模型的边界

模型管理只维护“系统有哪些可用模型”。业务功能只消费已配置模型：

- 需要文本生成的功能只列出已启用、已配置凭证的对话模型。
- 语音转写只列出已启用、已配置凭证的语音模型。
- 业务页面负责选择自己的模型；模型管理页不知道会议纪要、任务提取等业务名称。

现有能力策略接口可暂时保留在后端兼容旧调用，但从本页面移除，不作为本次页面的用户界面。

## 数据与接口

继续复用现有接口：

- `GET /api/ai-config/models`：加载模型卡片。
- `POST /api/ai-config/models`：新增模型。
- `PUT /api/ai-config/models/{id}`：编辑模型信息。
- `PATCH /api/ai-config/models/{id}/enabled`：启用或停用。
- `PUT /api/ai-config/models/{id}/credentials`：新增或替换 API Key。
- `POST /api/ai-config/models/{id}/test`：测试连接。

新增模型时，先创建模型记录，再保存 API Key。若模型创建成功而密钥保存失败，保留模型卡片并标记“缺少 API Key”，管理员可从编辑抽屉继续补充，不回滚已创建模型。

## 错误处理

- 模型列表加载失败：显示“模型加载失败”和“重新加载”，不显示空白页面。
- 表单校验失败：错误显示在对应字段下方。
- 密钥保存失败：模型保留，卡片显示“缺少 API Key”。
- 连接测试失败：抽屉底部显示失败状态，不关闭抽屉，不清空表单。
- 保存失败：保留当前输入并显示可理解的错误。
- 403：显示“仅技术管理员可以管理模型”。
- 503：显示“AI 配置服务暂不可用，请联系系统管理员”，不暴露环境变量名称。

## 安全要求

- API Key 输入框使用密码类型。
- 已保存密钥永不返回前端、永不回显。
- 错误提示、日志和页面 DOM 不得包含 API Key。
- 编辑模型时，只有明确执行“替换密钥”才调用凭证更新接口。

## 组件边界

- `AIConfigurationSection.tsx`：加载状态、分类筛选、模型卡片网格和抽屉开关。
- `AIModelCard.tsx`：单个模型摘要和模型操作。
- `AIModelDrawer.tsx`：新增与编辑表单、密钥管理、测试连接和保存。
- `aiModelProviders.ts`：服务商元数据、默认 Base URL、类型支持和内部 code 生成。

各组件只依赖现有 `aiConfig.ts` API，不引入业务能力策略数据。

## 验收

- 页面与确认的 WeKnora 式成品图一致：卡片网格、添加卡片、右侧抽屉。
- 只出现“全部 / 对话模型 / 语音模型”。
- 页面中不出现“会议纪要分析、任务提取、项目初始化分析、语音实时转写”等业务绑定项。
- 新增模型可在一个抽屉内完成服务商、模型名称、显示名称、Base URL 和 API Key 配置。
- 测试连接、保存、取消固定在抽屉底部。
- 编辑模型不回显密钥，并可替换密钥。
- 模型卡片支持编辑、测试、启用和停用。
- 前端生产构建通过；AI 配置 API 和密钥安全回归通过。
