# 关键任务月计划工作台设计

## 目标

将现有“关键任务详情”从以信息展示为主的页面升级为关键任务的执行工作台。关键任务保持原有三级业务主结构中的第三层；其下的月计划用于承载可重复、跨月、并行推进的执行分支，不成为新的正式业务层级。

用户从当前工作推进表点击关键任务后进入工作台。工作推进表的入口、整体视觉语言、返回路径和其他视图保持不变。

## 范围与边界

- 保持业务主结构：`项目 → 重点工作 → 关键任务`。
- 月计划属于关键任务的附属执行记录；一个关键任务可以有多个计划月份，一个月份可以有多条月计划。
- 不使用活动城市、场地等特定业务字段作为通用字段。活动、研发、招聘、交付等场景共享同一套通用月计划结构。
- 月计划的操作审计由系统自动记录，不作为业务表单字段对个人开放。
- 本期不改变工作推进表的整体布局，也不增加全新的侧边导航或独立模块入口。

## 月计划数据模型

月计划记录归属一个关键任务，核心字段如下。

| 类型 | 字段 | 规则 |
| --- | --- | --- |
| 必填 | 所属关键任务 | 系统自动绑定，不允许重复选择 |
| 必填 | 计划月份 | `YYYY-MM`；用于默认定位、分组、筛选与归档 |
| 必填 | 计划名称 | 当月要推进的具体事项 |
| 必填 | 预期产出 | 用可验证的交付结果表述 |
| 必填 | 执行负责人 | 默认继承关键任务负责人，允许改为该计划实际负责人 |
| 必填 | 状态 | 未开始、进行中、暂缓、已完成；已延期由截止时间与未完成状态动态判断 |
| 系统维护 | 排序权重 | 根据状态优先级和业务排序规则生成，用于同月展示 |
| 可选 | 起止日期 | 月内有明确时间窗口时填写 |
| 可选 | 协作人 | 多人协作时填写 |
| 可选 | 完成标准 | 该月产出需要独立验收时填写 |
| 可选 | 进展说明 | 当前动作、卡点及下一步 |
| 可选 | 风险与依赖 | 前置条件、跨部门协同或外部风险 |
| 可选 | 附件与成果链接 | 方案、纪要、交付材料等 |
| 系统维护 | 审计信息 | 创建、修改、状态变更、延期、删除的操作者、时间与前后内容；普通用户不可编辑 |

状态闭环规则：标记“已完成”时要求填写实际产出或完成说明；当已过截止日期且未完成时，系统展示为“已延期”；调整已延期计划时需填写延期原因并更新日期或计划月份。

## 页面结构与布局

进入关键任务后展示“关键任务执行工作台”。页面遵循当前系统的白底卡片、轻量边框与蓝色强调风格。

1. 顶部任务摘要栏
   - 保留“返回工作推进表”入口。
   - 展示重点工作、关键任务名称、直接负责人、整体状态、计划周期和完成标准。
   - 该栏描述父级关键任务的整体目标，不混入具体月计划的执行细节。

2. 主区域：月计划
   - 默认打开当前自然月；无本月计划时显示空状态与“新增月计划”入口。
   - 提供横向月份切换，可查看相邻月份和全部月份。
   - 月内计划以紧凑列表呈现，每条突出计划名称、预期产出、负责人、日期、进展/卡点和状态。
   - 点击一条月计划，打开详情编辑抽屉；抽屉展示和编辑完整的通用字段。
   - “新增月计划”在当前选中月份直接创建，自动继承关键任务负责人。

3. 右侧关键任务概览
   - 展示本月计划数、需关注项、月完成数、最新更新时间。
   - 展示最新过程记录，并提供入口查看完整的汇报、成果和问题。
   - 此区域保持关键任务级别，不把月计划与任务汇报混排。

4. 过程记录
   - 原有工作汇报、关联成果、关联问题及操作日志保留为独立区域或二级入口。
   - 月计划可以有简短进展更新；系统审计日志按权限查看，不干扰日常执行视图。

## 默认定位与排序

- 首次进入默认选中当前自然月。
- 按月份筛选后，只展示该月计划；“全部”按月份分组展示。
- 同一月份中的展示优先级固定为：`已延期 → 进行中 → 暂缓 → 未开始 → 已完成`。
- 同一状态内按截止日期升序；无截止日期的排在有截止日期记录之后；仍相同则按用户维护的业务排序和创建时间稳定排序。
- “已延期”是动态展示状态，不改变用户选择的基础状态值。

## 权限与异常处理

- 项目负责人、PM 可维护项目内全部月计划。
- 关键任务负责人可维护本人关键任务下的月计划。
- 执行负责人和有项目查看权限的成员可按现有范围查看；没有写权限的成员不能编辑。
- 已归档或已关闭项目禁止新增、编辑月计划；已完成、已取消计划停止提醒。
- 日期非法、负责人不属于项目、无权限写入等情况由后端拒绝并返回明确提示。

## 验收标准

- 从工作推进表点击关键任务后，能进入工作台并返回原列表。
- 默认打开当前月且月份切换正确。
- 同月支持多条月计划；按约定的状态优先级和截止日期排序。
- 新建时仅要求计划月份、计划名称、预期产出和执行负责人；其余字段按需填写。
- 月计划不会改写或破坏项目、重点工作、关键任务三级结构。
- 任务摘要、汇报、成果、问题和审计记录仍可查看，且职责层级清晰。
- 审计信息不在普通用户输入表单中出现，且可用于操作追溯。
