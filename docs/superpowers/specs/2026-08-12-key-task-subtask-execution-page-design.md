# 关键任务执行页与子任务布局设计

## 目标

点击工作推进表中的关键任务后，进入唯一的“关键任务执行页”。页面按已确认效果图重构，清晰呈现关键任务基本信息、子任务拆解和负责人针对该关键任务产生的执行过程。

本次改造不增加业务层级。业务主结构仍为项目、重点工作、关键任务；页面中的“子任务”是关键任务内部的执行拆解信息，工作汇报、成果、问题和会议纪要仍直接归属关键任务。

## 页面结构

### 关键任务标题区

- 保留“返回工作推进表”入口。
- 显示关键任务名称和状态。
- 显示所属重点工作和所属项目。
- 标题下方使用四栏概览卡片，字段依次为：负责人、协作人、开始时间、状态。
- “开始时间”从关键任务现有计划时间中提取；无法提取时显示未填写。
- 原“整体状态”统一改为“状态”。

### 子任务区

- 原“执行分工”和“月计划”相关界面用词统一改为“子任务”。
- 子任务列表采用效果图中的紧凑表格布局，包含状态、子任务事项、负责人、分组、时间安排、进度和操作。
- 月份只是子任务的可选分组，不是业务层级，也不是必填项。
- 默认提供“全部子任务”视图；用户可按已有月份筛选。
- 未选择月份的子任务正常创建和展示，分组显示为“未分月”。
- “新增子任务”打开右侧抽屉，只填写和维护子任务本身的信息。
- 点击子任务打开“子任务详情”右侧抽屉。

### 子任务详情抽屉

- 抽屉顶部显示子任务名称和状态。
- 负责人和协作人作为紧凑只读信息并排展示，不使用占据整行的协作人选择框。
- 分组、时间安排、进度、预期产出和完成标准按效果图展示。
- 只有进入编辑状态时才显示负责人和协作人的选择控件。
- 抽屉底部显示“提交汇报”“记录问题”“添加成果”“更多”。
- 这些动作复用现有工作汇报流程，并自动带入当前项目和关键任务。
- 不新增 `subtask_id` 之外的工作汇报归属，不让汇报、成果或问题归属到页面子任务。

### 执行过程

- 原“过程记录”统一改为“执行过程”。
- 执行过程展示负责人针对当前关键任务提交的工作汇报、成果、问题和会议纪要。
- 提供“全部、工作汇报、成果、问题、会议纪要”筛选。
- “提交工作汇报”进入现有唯一工作汇报入口，并自动带入当前项目和关键任务。
- 执行过程数据不按页面子任务切分，也不引入新的关联字段。

## 数据与兼容性

- 继续复用现有执行安排/月计划数据表和接口，前端业务名称改为“子任务”。
- 月份字段改为可选；历史已有月份的数据保持不变。
- 未分月记录与按月记录可以同时存在。
- 工作汇报、成果、问题和会议纪要继续使用现有关键任务详情数据与既有提交接口。
- 不修改项目、重点工作、关键任务的既有层级和权限规则。

## 权限与交互

- 有管理权限的用户可新增、编辑和删除子任务。
- 只读用户可查看子任务及执行过程，但不显示新增和编辑动作。
- 新增和编辑失败时抽屉保持打开并显示错误，不丢失输入。
- 归档或关闭的项目沿用现有禁止编辑规则。
- 桌面端按效果图实现右侧抽屉；窄屏下抽屉占满可用宽度，子任务表格允许横向滚动。

## 视觉要求

- 以确认的效果图为唯一视觉基准，复刻深色侧栏、浅色页面背景、白色卡片、蓝色主操作、状态色、紧凑表格、时间轴列表及右侧抽屉比例。
- 正式页面不包含原型编号、箭头或设计说明标注。
- 协作人不得在只读详情中独占一整行表单控件。

## 验收标准

- 从工作推进表点击关键任务进入关键任务执行页。
- 页面字段显示为负责人、协作人、开始时间、状态。
- 主模块显示“子任务”和“执行过程”，不存在“执行分工”或“月计划详情”等错误主语。
- 子任务月份可为空，空月份记录显示“未分月”。
- 子任务详情中负责人和协作人并排紧凑展示，没有整行协作人选择框。
- 工作汇报、问题和成果按钮进入现有工作汇报三条路径并预选当前项目与关键任务。
- 执行过程筛选、子任务新增/查看/编辑、权限态和错误态通过自动化测试。
- 前端生产构建通过，并在浏览器中对照效果图完成桌面和窄屏视觉验收。
