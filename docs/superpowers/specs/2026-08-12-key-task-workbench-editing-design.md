# 关键任务工作台统一编辑设计

## 目标

关键任务只有一个详情视角：本月计划工作台。工作推进表中的关键任务行进入该工作台；旧的“关键任务详情”居中弹窗不再作为详情或编辑入口。

## 交互

- 工作台标题区仅对有编辑权限的用户显示“编辑关键任务”。
- 点击后从右侧打开编辑抽屉，不遮挡本月计划、过程记录和任务概览。
- 抽屉保留旧弹窗全部基础字段：任务名称、责任人、协同人、计划时间、整体状态、完成标准。
- 保存成功后关闭抽屉，并刷新工作台标题、概览和工作推进表中的对应任务。
- 保存失败时抽屉保持打开并显示错误，不修改当前页面数据。

## 权限

- 技术管理员、项目负责人和项目协调人可编辑全部基础字段。
- 直接负责人沿用现有关键任务编辑规则。
- 其他用户只能查看工作台，不显示编辑动作。

## 实现边界

- 月计划分支的新增、编辑和删除继续由本月计划区负责。
- 任务基础字段仍使用既有关键任务更新接口，不新增数据表或接口。
- 工作推进表行点击必须调用统一的工作台入口，不能再渲染旧详情弹窗。
- 旧弹窗组件及其未使用状态从实际表格组件中移除；任务新增/独立管理流程不在本次调整范围内。

## 验证

- 自动化测试覆盖：表格行进入工作台；有权限用户可看到抽屉入口；抽屉包含全部六个字段；旧详情弹窗不再由表格组件渲染。
- 前端构建通过。
- 浏览器实际从工作推进表点击关键任务，验证进入工作台并可打开编辑抽屉。
