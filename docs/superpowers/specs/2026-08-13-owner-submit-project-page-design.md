# 完善项目方案：项目管理子页面设计

## 背景

“完善项目方案”当前以固定遮罩 Modal 呈现，虽然内容属于某个项目，却脱离了项目管理的导航与详情层级。负责人需要先理解弹窗语境，提交或取消后也缺少明确的页面归属。

## 已确认的体验

入口统一进入项目详情下的子页面：

`项目管理 → 项目详情 → 完善项目方案`

Dashboard 的待完善项目入口、项目管理列表入口和项目详情入口只负责导航到 `/home/projects/:projectId/owner-submit`。页面继续使用现有负责人填报表单、人员选择器、AI 草稿/合并/audit 和提交校验。

## 页面结构

新页面继续位于既有 `ProjectLayout` 内，因此保留项目管理侧栏和正常页面背景。页面自身由工作台容器组成：

- 顶部：标题与“返回项目详情”操作；
- 主区：现有项目资料与重点工作表单，可在内容较多时独立滚动；
- 底部：保留取消和提交审核，取消与标题返回都回到项目详情。

工作台不再使用 `fixed inset-0`、遮罩或点击背景关闭；也不再以 viewport 宽高作为 Modal 尺寸。项目页容器提供可用高度，工作台在该容器内填充并保持 Header/Main/Footer 三段式。

## 保持不变的边界

- 项目资料、重点工作、折叠/展开、任务表格、颜色与字号；
- `AssigneePicker`、`HelperPicker`；
- AI 草稿、合并、audit；
- 负责人提交校验、API、后端和数据库。

## 验收

1. 三个已有入口都进入同一个项目详情子路由。
2. 直接访问该 URL 能加载项目并显示工作台。
3. 页面有项目管理侧栏，无遮罩层，无独立 Modal 外壳。
4. 取消、返回和成功提交均回到对应项目详情。
5. 原有布局与 AI 回归测试继续通过，新增路由迁移测试覆盖入口和容器边界。
