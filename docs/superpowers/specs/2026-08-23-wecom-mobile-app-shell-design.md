# 企业微信移动端应用外壳设计

## 目标

将当前手机宽度下“缩窄的桌面后台”改为企业微信工作台式应用外壳。首要场景是冯海林（CEO）查看首页驾驶舱，但导航与权限逻辑同时适用于其他角色。

## 范围与断点

- 视口宽度小于 `800px` 时启用移动应用外壳；`800px` 及以上保留现有桌面侧边栏与布局。
- 移动端隐藏现有 `Sidebar`，主内容区使用完整屏幕宽度。
- 固定底部导航的高度由内容区预留，滚动内容不得被导航遮挡。
- 不变更 API、业务数据、鉴权模型、现有路由或桌面端组件行为。

## 移动导航

### 底部主导航

移动端固定显示四个入口：

1. 首页：有驾驶舱权限的用户进入 `/home/dashboard`；普通成员进入个人任务中心。
2. 任务：复用当前角色对应的任务入口。
3. 确认：有确认中心权限的用户进入 AI 确认中心；无此权限时改为该角色最常用的可访问工作入口。
4. 更多：打开移动端底部抽屉，不直接跳转到新页面。

冯海林的固定顺序为“首页、任务、确认、更多”。

### 更多抽屉

点击“更多”从底部打开覆盖层，显示当前用户有权访问的既有模块：工作汇报、会议纪要、成果库、问题中心、组织管理、项目管理、通知中心、系统设置、修改密码、退出登录。

- 仅显示既有权限判断允许的模块。
- 每个模块调用已有导航逻辑，抽屉随后关闭。
- 点击遮罩、关闭按钮或完成跳转均关闭抽屉。
- 修改密码与退出登录继续调用现有回调，不复制业务逻辑。

## 共享导航来源

将当前 `Sidebar` 内的导航条件与条目定义抽成共享的纯函数或轻量模块。桌面侧栏、移动底部导航与移动“更多”抽屉共同消费该定义，确保角色权限、通知入口与未来新增模块不会分叉。

## 首页视觉与内容区域

- `MobileDashboardContent` 在移动外壳中使用整屏可用宽度：375px 视口下为 16px 左右留白与 343px 内容宽度。
- 顶部继续保留“首页驾驶舱”和通知中心入口；不再显示桌面侧栏的图标轨。
- 风险待办、任务概览、本月重点等已确认的风险优先顺序保持不变。
- 内容底部增加固定导航避让距离；不在移动端重建 Chart.js。

## 组件边界

- `ProjectLayout`：根据断点同时承载桌面 Sidebar 或移动应用导航，保持路由与项目上下文职责。
- `MobileAppNavigation`：渲染底部四栏与更多抽屉，只接收已解析的导航条目、当前页和回调。
- 共享导航模块：计算桌面与移动均可用的入口及权限过滤结果。
- `MobileDashboardContent`：仅渲染首页内容与首页内筛选、数据、动作，不管理全局导航。

## 验收与测试

- 结构测试验证：移动宽度下桌面 Sidebar 隐藏、移动导航出现、桌面宽度不受影响。
- 测试更多抽屉的权限过滤、关闭行为和既有路由回调复用。
- 测试首页移动内容拥有底部导航避让空间。
- 在冯海林账号下以 `375×812` 检查：没有左侧图标栏、内容宽度完整、底部四栏可见、更多抽屉入口可用、页面无横向滚动。
