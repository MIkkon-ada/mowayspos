# 企业微信移动端核心页面改造设计

## 目标

为企业微信工作台的手机视图补齐四个高频业务页面：任务、确认、会议纪要、问题与决策。保留现有权限判断、接口、路由与桌面端表现，仅在小于 800px 的视口中采用适合手机的单列信息结构。

## 统一原则

- 页面继续使用既有 `ProjectLayout` 的手机壳层：顶部内容区与固定底部导航；内容底部预留导航高度。
- 桌面端（800px 及以上）不改变原有表格、侧栏和详情工作区布局。
- 所有权限仍由既有权限函数与路由控制；手机端不显示用户无权使用的入口或操作。
- 手机列表优先呈现处理判断所需的信息，完整记录进入全屏详情或既有抽屉后按需展开。

## 任务页

- 顶部使用项目与状态筛选，筛选区域在手机上纵向或两列自适应排列。
- 桌面推进表在手机端替换为纵向任务卡；每张卡展示任务标题、负责人、计划截止时间、状态和完成进度。
- 点击任务进入既有关键任务执行详情；手机详情采用全屏阅读，不在窄屏展示横向表格。
- 可操作用户在详情底部看到与当前权限相符的固定操作区，例如更新进度、提交汇报或新增处理项。

## 确认页

- 手机端将确认项目展示为待确认事项流，而不是多列表格。
- 每个事项卡展示待确认内容、发起人、影响说明、状态和必要的时间信息。
- 卡片展开或进入详情后显示确认依据、关联事项与备注。
- 有确认权限的用户在详情底部可执行确认或退回；退回沿用现有理由校验与请求逻辑。

## 会议页

- 手机端首页为会议时间线，按日期展示会议主题、所属项目与待办数量。
- 会议详情的首屏依次为结论、待办、风险；原始纪要、附件与其他详细内容折叠在后续区块。
- 会议的创建、编辑、变更审核与现有权限规则不改变；复杂编辑表单维持既有流程，并在手机端避免横向溢出。

## 问题与决策页

- 手机端将问题展示为风险卡片流，使用红、黄、绿状态色区分紧急程度。
- 卡片展示问题标题、责任人、截止时间、处理状态和最新动作。
- 点击卡片进入全屏详情，按时间线显示处理记录、关联任务和决策信息。
- 仅向有权限的用户展示处理、升级或关闭动作；所有提交仍调用既有接口。

## 验收标准

- 375px 宽度下，四个页面的主内容无水平滚动，且不会被固定底部导航遮挡。
- 四个页面均保留对应页面已有的加载、空状态和错误状态。
- 任务卡、确认事项、会议卡与问题卡均可进入原有详情或操作流程。
- 800px 及以上的桌面页面结构保持不变。
- 冯海林等不同权限用户只看到其授权入口与操作。

## 非目标

- 不改变接口、数据库或权限模型。
- 不重做后台管理、项目管理、成果库、账号设置等低频页面；它们通过“更多”入口维持现有桌面式内容，后续可单独优化。
