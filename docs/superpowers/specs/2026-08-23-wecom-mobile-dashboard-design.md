# 企业微信移动端首页驾驶舱设计

## 范围

为现有 `DashboardPage` 增加企业微信移动端布局。保留当前桌面端布局、路由、权限、数据接口和统计计算；本阶段不处理任务、成果、会议等其他业务页面。

移动端按 375px CSS 像素设计，最低支持 360px 宽度且页面主体不得出现横向溢出。

## 设计目标

采用“风险优先”首页：用户进入企业微信工作台后，先看到需要立即处理的延期任务和角色待办，再查看概览、重点任务和项目进度。

## 信息结构

页面按以下顺序纵向滚动：

1. 顶栏：`首页驾驶舱`、通知入口。
2. 筛选：现有项目范围选择和月份选择；手机端在同一行等宽排列，空间不足时允许纵向排列。
3. 风险与待办：`延期任务` 与当前角色队列并列展示；角色队列标题与现有逻辑一致，分别为 `需决策事项`、`待审核内容`、`待给出建议` 或 `流程推进中`。
4. 任务概览：任务总数、进行中、已完成为一行摘要；延期、待决策、成果数量仍可见，作为同区补充指标。
5. 本月重点：复用现有最近任务数据，显示前三项和“查看更多”。
6. 延期任务：复用现有延迟任务数据，显示任务名称、超期/延期状态、项目、负责人和计划时间。
7. 角色待办：复用 `role_queue`，显示前三项和现有跳转目标。
8. 专项进度总览：复用各项目完成率计算，单列显示项目进度条。
9. 任务状态分布：复用现有状态统计和圆环图数据，缩小图表并保留图例。

## 布局规则

- 内容区左右内边距 16px，375px 屏幕的有效内容宽度为 343px。
- 统计数据不删除，但从桌面的 5/6 列卡片改为紧凑摘要；风险和待办不依赖横向滚动。
- 当前桌面端三栏的“本月重点 / 延迟任务 / 角色待办”在移动端拆为纵向三段，顺序为重点、延期、角色待办；首屏额外提供延期和角色待办数量入口。
- 现有桌面端“专项进度总览 + 状态分布”从同一行拆成上下两个独立区块。
- 任务标题允许两行显示；项目、负责人和时间为次级信息，长文本省略。
- 需要进入完整列表的区块继续使用现有“查看更多”和对应路由，不在首页复制列表功能。

## 角色与数据

- 不新增接口、字段或统计口径。
- `canViewDecisions`、`role_queue.type`、项目范围和月份选择维持当前行为。
- 没有数据时沿用现有空态文字；加载中、刷新失败和无权限状态保留，但需要按单列布局显示。
- 点击统计项、延期任务、重点任务、角色待办和进度项目继续使用当前导航目的地。

## 验收

- 在 360px、375px、390px 宽度下，首页不产生页面级横向滚动。
- 延期任务和角色待办在首屏可见，无需先浏览统计和图表。
- 六项统计、三个业务列表、项目进度和状态分布均可访问。
- 不同角色显示正确的动态角色待办标题和跳转入口。
- 桌面端 800px 及以上的既有布局和交互不回归。
