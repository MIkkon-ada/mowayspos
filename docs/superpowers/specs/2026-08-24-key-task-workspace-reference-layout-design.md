# 关键任务执行工作台参考图布局设计

## 目标

将关键任务执行工作台的桌面端视觉结构替换为用户提供的两张参考图：浅蓝顶部信息区、左侧执行内容与右侧所属关系卡、任务计划后的双卡区域，以及底部推进记录。保留现有数据、权限和交互能力。

## 范围

### 包含

- 顶部信息区显示任务路径、标题、状态、负责人、协同人、计划时间及现有操作按钮。
- 工作台采用左侧主内容与右侧所属关系卡的两栏布局；桌面端右侧卡保持吸顶。
- 主内容按“当前进展、任务计划、成果与交付/问题与风险双卡、推进记录”的顺序排列。
- 任务计划、当前进展、成果、问题和推进记录的无数据状态使用参考图的紧凑卡片式布局与中文提示。
- 有数据时继续渲染现有表格、时间线、权限控制和任务计划详情抽屉。
- 在窄屏下保持单列响应式布局，避免横向截断关键内容。

### 不包含

- 不变更 API DTO、后端接口、数据库或任务权限规则。
- 不变更提交更新、风险标记、确认完成、重新打开或计划详情抽屉的行为。
- 不将截图作为页面静态图片或新增图片资源。

## 组件设计

`KeyTaskExecutionWorkspace` 继续负责加载、权限动作、主次栏布局和详情抽屉。各展示组件保持各自数据边界：

- `KeyTaskHeader` 改为全宽浅蓝信息区，并保留操作区。
- `CurrentProgressCard` 使用参考图的蓝色边框标题和居中空状态。
- `ExecutionPlanTable` 使用参考图的统计行、表头与居中“添加计划”空状态；有计划时保留现有点击行打开抽屉的行为。
- `AchievementList` 与 `IssueList` 仅在桌面端组成并排双卡；有内容时仍各自渲染原表格。
- `ExecutionTimeline` 使用标题行右对齐筛选标签及参考图时间线空状态。
- `KeyTaskContextCard` 保留数据字段，但对齐参考图的右侧关系卡视觉密度。

## 数据与交互

所有组件继续只消费现有 `KeyTaskWorkspace` 数据。没有当前进展、计划、成果、问题或推进记录时，显示对应空状态；存在数据时使用原有内容。按钮、权限条件、抽屉打开、筛选、风险变更和任务完成确认均不改变。

## 测试与验收

在修改生产代码前，扩展 `keyTaskExecutionWorkspace.test.mjs`，覆盖：

- 工作台主区的组件顺序和“成果/问题”共享双栏容器。
- 顶部信息区、右侧关系卡和任务计划统计继续存在。
- 任务计划空状态包含添加计划入口；各其他空状态仍提供正确提示。
- 已有接口、抽屉与权限相关结构测试继续通过。

验收通过的条件是：目标单测先红后绿、前端 TypeScript/Vite 构建成功，并在桌面宽度下人工核对页面层级与两张参考图一致。
