# 会议纪要项目选择页视觉对齐设计

## 目标

仅将“会议纪要”的无项目上下文页（项目选择列表）视觉尽可能对齐用户提供的参考图。不改变项目数据、搜索规则、会议加载、新建会议或跳转逻辑。

## 范围

- 修改 `frontend/src/pages/MeetingPage.tsx` 中 `!effectiveProjectId` 的项目选择视图。
- 仅在必要时为该视图添加有命名空间的局部 CSS，不覆盖其他页面。
- 保留现有的桌面端响应式头部结构和移动端降级能力。

## 视觉规格

1. 页面使用白色 64px 顶栏：左侧是“会议纪要”，右侧保留项目搜索与“新建会议纪要”按钮。
2. 主区为浅灰背景，宽度与参考图一致：标题“选择项目”、说明文案和右侧项目数量对齐。
3. 项目表格为白色圆角卡片，带轻微阴影和细分隔线；字段依次是项目名称、状态、项目经理、最近会议、操作。
4. 每行用项目首字符生成语义化的色块图标；“进行中”显示绿色胶囊，“未启用”显示灰色胶囊。
5. 右侧操作保留单个可点击模式，文案为“查看会议纪要”并带箭头；点击行本身也继续选择项目。

## 行为与边界

- 搜索框仍按项目名称、编号、项目经理过滤，并反映到项目数量。
- 无项目上下文时“新建会议纪要”仍禁用，保留现有提示。
- 不引入图片资产或新的第三方依赖；图标由内联 SVG 和现有文字生成。
- 不修改 API、数据字段、路由或后端代码。

## 验收与回归

- 先更新一个面向用户结构的前端测试，验证项目选择页包含标题、搜索、五列表格、状态标签和可访问的查看操作。
- 执行该测试并观察其在实施前失败。
- 实施后运行前端类型检查与产物构建（`npm run build`），再运行会议相关和页面布局测试。
- 对比 1280px 宽度的页面截图与参考图，检查栏高、间距、颜色、表格圆角和文字层级。
