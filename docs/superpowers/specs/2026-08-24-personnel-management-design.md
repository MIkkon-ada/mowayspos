# 人员与账号管理规范化设计

**日期：** 2026-08-24
**状态：** 已确认，待实施计划

## 目标

将现有按人员卡片平铺的页面调整为适合后台批量管理的界面：以表格快速总览与检索人员，以右侧详情抽屉处理单个人员的账号、权限与企业微信身份信息。页面应清晰区分企业微信来源资料与本系统管理资料，避免在卡片内混排表单、危险操作和身份信息。

## 已确认的业务边界

| 信息 | 权威来源 | 页面规则 |
| --- | --- | --- |
| 姓名 | 本系统人员档案 | 可按既有人员管理流程创建和维护 |
| 企业微信 ID、部门、岗位/职务 | 企业微信 | 原样展示，不做枚举或本地约束；同步确认后覆盖本系统显示值 |
| 系统角色 | 本系统 | 为系统内权限角色，独立于企业微信职务 |
| 登录账号、密码、启用状态 | 本系统 | 仅由本系统管理员维护 |

企业微信部门或岗位发生变化时，管理员通过同步预览确认后，企业微信资料覆盖本系统当前值。未绑定企业微信的人员可正常存在，但部门与岗位显示为空或“待绑定”，不得手工录入为本地值。

## 页面架构

### 总览表格

页面顶部保留以下全局动作：批量导入人员、拉取企业微信通讯录、同步部门/岗位、新建人员。动作视觉层级为：新建人员为主按钮，其余为次级按钮；同步与通讯录动作与企业微信关联。

表格列为：

1. 人员 / 登录账号
2. 部门 · 岗位
3. 系统角色
4. 企业微信绑定状态
5. 账号状态
6. 操作入口

支持按姓名或账号检索，并提供部门和账号状态筛选。每一行可点击打开人员详情抽屉，列表不再内嵌密码输入、禁用和解绑操作。

### 人员详情抽屉

抽屉以当前人员姓名、账号和账号状态作为头部。内容固定分为三个区块：

1. **企业微信身份（只读）**：企业微信 ID、部门、岗位/职务、绑定状态，以及“同步来源；下次同步将自动更新”的提示。
2. **系统权限**：系统角色的查看与调整入口。该角色不受企业微信部门或职务影响。
3. **账号与安全**：账号名、重置密码、启用/停用账号。删除人员放在“更多操作”中，始终需要二次确认。

未绑定人员在企业微信区块显示“待绑定”，可进入既有的通讯录匹配/绑定流程；不得展示手填部门或岗位的控件。

## 同步流程与异常处理

“同步部门/岗位”继续使用现有的“读取通讯录 → 预览 → 管理员确认写入”流程。预览应区分已匹配成员、将更新的资料、待新建或未匹配成员；用户只确认选中的变更。确认成功后重新加载总览和详情数据。

同步失败时，界面保留当前已展示资料并展示可理解的服务端错误，包括：通讯录权限未配置、企业微信成员已变化、账号或企业微信 ID 冲突。不得以失败或空响应清空原资料。

## 组件与数据流

将现有 `AccountPeopleMgmtSection` 的职责拆分为：

- `PeopleManagementToolbar`：全局导入、通讯录和新建动作。
- `PeopleManagementTable`：筛选、表格呈现与选择人员。
- `PersonDetailDrawer`：单人资料展示与本地账号安全操作。
- 保留并复用 `WecomIdentitySyncModal` 与 `PeopleBatchImportModal`；企业微信身份同步 API 不改变。

父组件统一读取 `fetchPeople()` 与 `fetchAccounts()` 并以 `person_id` 关联。同步、绑定、账号状态变更或删除成功后调用统一刷新函数，以避免表格与抽屉出现不一致。

为符合企业微信为身份资料唯一来源的规则，人员编辑请求仅可提交姓名和系统角色；不再从此页面提交部门或岗位的手动更改，也不再需要“恢复企业微信值”的单字段操作。

## 验收与测试

- 表格正确关联人员、账号、企业微信绑定和状态；检索与筛选结果正确。
- 点击行打开和关闭抽屉；企业微信资料在抽屉中只读。
- 人员编辑只变更允许的本地字段；系统角色不受企业微信同步影响。
- 同步预览确认后，部门/岗位按企业微信值更新；取消或失败不修改现有资料。
- 重置密码、启用/停用、解绑和删除均保留当前确认与错误反馈规则。
- 覆盖无账号、未绑定企业微信、禁用账号、绑定冲突和通讯录权限不足状态。

## 非目标

- 不添加企业微信定时后台自动同步；本次只规范手动触发、预览确认的同步流程。
- 不改动企业微信 API 及其现有的身份匹配策略。
- 不重新定义系统角色或企业微信组织结构。
