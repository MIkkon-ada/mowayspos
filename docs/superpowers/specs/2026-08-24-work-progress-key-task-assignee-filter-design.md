# 工作推进表关键任务责任人筛选设计

## 目标

工作推进表顶部的“负责人”下拉仅展示当前选定项目中已分派关键任务的责任人，并以关键任务 `assignee` 作为筛选依据。项目负责人、协同人及未承担关键任务的项目成员不应进入该下拉。

## 方案

页面继续使用已存在的批量关键任务读取结果 `taskSubMap`，不新增或调整接口。

1. 在当前项目的重点工作对应关键任务已加载后，读取每条关键任务的非空 `assignee`。
2. 对责任人名称去重，并作为“全部负责人”下拉的选项；名单不读取项目 `owners` 或协同人字段。
3. 选定责任人时，仅保留至少包含一条该责任人关键任务的重点工作；该重点工作及其匹配的关键任务继续由现有视图组件展示。
4. 项目切换或关键任务列表更新后，如果当前已选责任人不属于新名单，清空筛选值，避免产生无意义的空结果。

## 边界与失败处理

- 关键任务尚未加载完成时，下拉只显示“全部负责人”；加载完成后自动更新。
- 当前项目没有关键任务或所有关键任务都未指定责任人时，下拉只显示“全部负责人”。
- 不包含关键任务协同人，不回退项目负责人，不新增网络请求。

## 验证

添加前端回归测试，验证：

1. 负责人选项来自关键任务 `assignee`，不包含项目 `owners`。
2. 选择负责人后，只保留拥有该责任人关键任务的重点工作。
3. 切换项目后，若原负责人不在新项目关键任务负责人集合中，筛选值会清空。
