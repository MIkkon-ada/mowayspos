# 工作推进表：最新已确认提交与状态标记设计

**日期：** 2026-08-24  
**范围：** 工作推进表的桌面表格视图；不改变项目、重点工作、关键任务的层级或权限规则。

## 目标

将当前最右侧“状态”列替换为“最新已确认提交”，让推进表首先回答“这项工作最近有什么正式进展”。

关键任务的状态不再以一列重复的“进行中”蓝框表达；改为紧贴任务名称的语义标记，使风险、延期、暂停和完成可被快速扫读。

## 界面设计

表格保留五列：重点工作、关键任务、负责人、计划时间、最新已确认提交。

“最新已确认提交”单元格显示：

- 第一行：`确认日期 · 提交人`。
- 第二行：已确认提交的精简摘要；长文本按现有表格密度截断，点击关键任务仍进入详情查看全文。
- 没有已确认记录时显示灰色占位文案“暂无已确认提交”。

关键任务名称后可显示多个紧凑标记：

| 标记 | 颜色 | 含义与判定 |
| --- | --- | --- |
| `未开始` | 灰色 | 任务处于未开始状态。 |
| `暂缓` | 灰蓝色 | 项目成员显式将任务标记为暂缓/暂停。 |
| `有风险` | 橙色 | 负责人或项目经理人工标记；需在详情保留风险说明。 |
| `已延期` | 红色 | 有明确计划截止日期、当前未完成，且当前日期已超过截止日期。 |
| `已完成` | 绿色 | 任务状态为已完成。 |

`进行中`不显示标签，减少全表重复视觉噪声。若任务既“有风险”又“已延期”，两个标签同时显示；红色延期标记优先靠近任务名称。任务已完成后不再显示“已延期”，如需保留历史逾期信息，应在详情时间线查看，而不是在推进表制造冲突信号。

## 数据与判定

### 最新已确认提交

按关键任务 ID 精确读取已确认工作提交：

1. 仅取已确认的数据，即 `confirmed_at` 有值的记录。
2. 仅取 `related_subtask_id` 等于当前关键任务 ID 的记录，禁止以重点工作 ID 聚合，避免同一重点工作下的进展串行。
3. 按 `confirmed_at` 倒序，取第一条。
4. 使用提交人、确认时间和可读摘要构造单元格；数据缺失时使用统一占位，不回退到未确认草稿。

现有 `UpdateSubmission` 已具有 `related_subtask_id` 与 `confirmed_at`，因此该读取规则可以基于已确认的正式记录建立。

### 自动延期

自动延期只处理能解析为明确截止日期的计划时间；无日期、持续性计划、模糊文本均不自动标红。判断规则为：

`未完成` 且 `计划截止日期 < 当前业务日期` → `已延期`。

原始计划时间如只有单日，单日即截止日；日期范围以结束日期为截止日。解析失败不猜测、不标延期。

### 人工风险

人工风险是独立于延期的业务判断。负责人和拥有既有任务管理权限的项目角色可以添加或解除“有风险”，并填写原因；普通查看者只能查看。风险原因在表格中不展开，点击关键任务后查看，避免表格变成问题清单。

## 交互与权限

- 点击关键任务的现有行为不变，继续进入关键任务执行详情。
- 最新提交单元格为只读摘要；不直接编辑或确认提交。
- 风险标记的新增、修改、解除沿用关键任务的既有写权限；后端必须校验权限，前端只做辅助隐藏。
- 未确认提交只可在详情/确认流程中看到，不得进入推进表的“最新已确认提交”。

## 验收标准

1. 表头不再有“状态”，替换为“最新已确认提交”。
2. 每个关键任务最多展示其最新一条、且精确关联的已确认提交。
3. 无已确认提交时显示“暂无已确认提交”，不得展示草稿或其他关键任务的记录。
4. “进行中”不显示标签；未开始、暂缓、有风险、已延期、已完成具有上述可区分的标签与颜色。
5. 明确到期且未完成的任务自动显示“已延期”；模糊或持续计划不自动标延期。
6. “有风险”和“已延期”可同时显示；已完成任务不显示“已延期”。
7. 现有项目过滤、搜索、任务详情跳转和权限控制不回归。

## 不在本次范围

- 不修改历史提交内容或确认流程。
- 不把成果、问题、会议纪要混入“最新已确认提交”。
- 不改变重点工作层级的字段或汇总规则。
