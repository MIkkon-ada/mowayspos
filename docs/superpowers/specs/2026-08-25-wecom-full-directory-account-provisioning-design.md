# 企业微信全员通讯录与账号自动创建设计

## 目标

管理员从“人员与账号管理”一键读取企业微信根部门及其全部子部门成员。系统应同步企业成员的姓名、企业微信唯一 ID、完整部门归属和岗位；为没有本地账号的成员自动创建人员档案和登录账号。

## 已确认规则

- 读取范围为根部门及全部子部门。
- 同步企业微信 `userid`、姓名、完整部门路径和岗位。
- 已按企业微信 `userid` 绑定的成员：更新对应人员的部门和岗位；如果该人员没有登录账号，则补建账号。
- 未绑定但姓名唯一匹配本地人员的成员：绑定该人员、更新部门和岗位；如果没有登录账号，则补建账号。
- 企业微信中的新成员：创建本地人员档案，并创建登录账号。
- 姓名匹配到多名本地人员，或企业微信 ID 已被其他人员占用时：标记为冲突，不自动写入或创建账号。
- 新账号用户名优先使用企业微信 `userid`；若已被占用，以递增编号生成唯一用户名，例如 `zhangsan-2`。
- 新账号初始密码为 `123456`，账号启用，且不启用首次登录强制改密。
- 自动创建的人员是普通成员；不授予技术管理员、系统管理员或项目成员权限。

## 数据流

1. 管理员打开“同步企业微信部门/岗位”并选择“同步全员并创建账号”。
2. 后端读取企业微信成员详情和部门树，生成部门完整路径。
3. 后端逐人按已绑定 ID、唯一姓名、本地新建、冲突的顺序决策。
4. 对可处理成员，在一个事务中写入人员身份资料；必要时创建并绑定本地账号。
5. 返回总人数、更新人数、新建人员数、新建账号数和冲突名单，前端展示结果。

## 安全与边界

- 仅技术管理员可执行。
- 导入不删除本地人员或账号，不重置已有账号密码。
- 导入不改系统角色、项目角色和项目成员关系。
- 企微接口失败、权限不足或任一数据冲突时，错误应明确返回；冲突成员不应影响其他可处理成员。

## 验收标准

- 企业微信根部门下所有子部门成员均被读取，并保存完整部门路径与岗位。
- 已绑定成员仅更新企业身份资料；缺账号成员获得账号。
- 新成员获得人员档案、唯一用户名、初始密码 `123456`、启用状态和 `must_change_password=false`。
- 重名或 ID 冲突成员未被自动错误关联，并在结果中可见。
- 现有角色、项目权限和既有账号密码保持不变。
