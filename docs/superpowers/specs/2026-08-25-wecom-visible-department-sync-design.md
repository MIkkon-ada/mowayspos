# 企业微信可见部门通讯录同步设计

## 背景

人员管理当前固定以企业微信根部门（`department_id=1`）递归读取成员。企业微信应用仅被授予咨询部、商务部、人力资源部、总经办、人才发展部、投融资部的可见范围，因此请求根部门会得到 `60011`。

## 目标

“拉取企微通讯录”和“同步部门/岗位”只读取企业微信应用可见范围内的部门成员，不要求全员权限。当前目标范围为上述六个一级部门，均无下级部门。

## 方案

后端新增一条共享的“可见部门目录”读取路径：

1. 调用企业微信部门列表接口，取得当前应用可见的部门。
2. 忽略根部门，将其余可见部门逐个作为 `department_id` 调用成员列表接口，使用 `fetch_child=0`。
3. 按企业微信 `userid` 合并、去重成员；若成员属于多个可见部门，只返回一次。
4. 批量账号绑定、身份预览、确认同步和账号创建均复用该路径，不再向根部门 `1` 请求成员。

接口路径保持不变。部门/岗位路径继续由部门列表构建；缺少上级部门时展示可见部门名称，不阻塞同步。

## 用户界面与权限

前端不增加第二套部门选择器，企业微信管理后台的应用可见范围是唯一授权来源。人员管理页面的“同步全员并创建账号”文案改为“同步范围内人员并创建账号”，避免表示为企业全员。

企业微信返回 `60011` 时，错误提示应说明“应用对所请求部门无查看权限或部门不在可见范围”，不再笼统归因于未开通讯录权限。

## 测试

- 可见部门按 ID 分别请求，且每个请求不递归子部门。
- 多部门返回相同成员时仅保留一条。
- 两种成员读取接口都使用该范围。
- 原有根部门 `1` 拉取路径不再被人员管理接口调用。
- 前端文案不再表示同步企业全员。
