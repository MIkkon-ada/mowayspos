# 工作推进表默认项目设计

## 目标

用户从侧边栏进入工作推进表且链接没有指定项目时，直接显示当前账号第一个可访问的项目，避免先停留在“请选择项目”空态。

## 方案

保留现有项目上下文优先级：手动选择项目或 URL 中的 `projectId` 优先；只有两者都不存在时，页面自动选中可用项目列表中的第一个项目。

“可用项目”继续沿用当前页面定义：当前账号可见，且项目状态为执行中或已归档。顶部项目下拉仍可切换项目；用户主动清空选择后，页面也会恢复到第一个可用项目，确保侧边栏入口始终有默认内容。

## 边界与失败处理

- 没有可用项目时，保持现有“当前没有可查看的项目工作推进表”提示。
- URL 中携带有效 `projectId` 时，不改写、不覆盖该项目。
- 项目管理页的“进入工作推进表”继续携带 `projectId`，不受本调整影响。
- 不新增接口、不持久化上次选择，也不改写浏览器地址。

## 验证

添加前端回归测试，覆盖：

1. 没有 URL 项目上下文时，第一个可用项目会被自动选中。
2. URL 项目上下文优先于自动默认选择。
3. 没有可用项目时，保留空态行为。
