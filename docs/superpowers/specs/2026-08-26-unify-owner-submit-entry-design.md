# 统一项目负责人立项完善入口设计

## 背景

项目处于草稿、待完善或退回状态时，页面会提示项目负责人补齐项目方案中的重点工作和关键任务。但项目基础资料编辑入口（`/home/projects?edit=:id`）只包含基本信息和团队配置；它不能维护工作推进方案。若负责人被导向该入口，用户无法完成待办中列出的任务。

现有的项目方案页已经提供完整能力：`/home/projects/:id/owner-submit` 可维护重点工作及其关键任务，并提交审核。

## 目标

让项目负责人从每一个“完善立项信息”“继续完善项目”“修改项目计划”入口进入同一个项目方案页；将项目基础资料编辑保留给公司 CEO、超级管理员等具有编辑权限的角色。

## 非目标

- 不将重点工作或关键任务嵌入“编辑项目”弹窗。
- 不修改项目生命周期状态值、后端接口路径或审批规则。
- 不改变执行阶段的工作推进表入口。

## 用户与路由规则

| 当前用户与项目状态 | 用户操作 | 目标页面 |
| --- | --- | --- |
| 项目负责人；`draft`、`dispatched` 或 `returned` | 完善/继续完善/修改项目计划 | `/home/projects/:id/owner-submit` |
| 公司 CEO 或超级管理员；可编辑草稿项目 | 编辑项目 | `/home/projects?edit=:id` |
| 其他角色或无权角色 | 查看项目 | 项目详情页，不提供方案提交操作 |

项目负责人同时具备其他角色时，选择“完善立项信息”语义的入口仍优先进入项目方案页；管理员“编辑项目”入口保持独立且文案明确。

## 统一入口设计

前端只保留两类清晰的项目操作意图：

1. `ownerSubmit`：负责人编辑并提交项目方案。所有调用处使用项目 ID 构造 `/home/projects/:id/owner-submit`。
2. `edit`：管理员编辑项目基础资料和团队。所有调用处使用 `?edit=:id` 打开编辑弹窗。

排查范围包括项目待办卡片、项目管理列表、项目详情页、仪表盘待完善项目卡片、通知中心及任何携带 `edit` 查询参数或调用 `openProjectEditor` 的项目入口。发现的负责人方案操作不得再复用 `edit` 入口。

## 权限与错误处理

项目方案页继续由既有的项目查看能力路由守卫保护。页面加载后应使用项目成员角色确认当前用户是实际项目负责人；不满足条件时不渲染可提交方案表单，显示无权访问提示并提供返回项目详情的路径。后端仍是最终写权限判定者。

无效项目 ID、项目加载失败和后端拒绝提交沿用当前页面的错误提示，不产生静默跳转至编辑项目弹窗的降级行为。

## 验收标准

1. 项目负责人从任意立项完善入口均进入 `/home/projects/:id/owner-submit`。
2. 进入项目方案页后，可以新增重点工作，并在每项重点工作下新增关键任务。
3. 管理员的“编辑项目”仍进入 `?edit=:id`，且弹窗不承担项目方案维护职责。
4. 非负责人无法通过直接输入 `owner-submit` URL 获得提交权限。
5. 覆盖上述入口与权限规则的自动化测试通过；使用项目 ID 4 完成一次浏览器回归。
