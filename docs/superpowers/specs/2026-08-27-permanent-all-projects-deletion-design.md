# 全部项目永久删除设计

## 目标

让技术管理员可以永久删除任意生命周期状态的项目，并清理该项目的数据库关联数据及受控存储目录中的实际附件文件。该操作不可从应用内恢复。

## 范围与权限

- 仅 `is_tech_admin`（项目能力中的 `super_admin`）可看到入口和调用删除接口。
- 项目状态不构成限制：`draft`、`dispatched`、`active`、`pending_close`、`ended`、`archived` 均可删除。
- 不提供批量删除、模糊名称删除或绕过确认的接口。
- 现有非技术管理员无权删除，前端不显示入口，后端仍返回 403。

## 用户交互

1. 技术管理员在任意项目卡片的 `⋯` 菜单中点击红色“永久删除项目”。
2. 弹窗显示项目名称、当前状态、不可恢复警告和将清理的数据类别。
3. 操作者必须输入完整项目名称及固定文字“永久删除”。两项均精确匹配后，提交按钮才可用。
4. 提交期间界面防止重复请求。成功后关闭弹窗、移除卡片、刷新项目列表和相关仪表盘缓存；失败时保留弹窗并显示服务端原因。

## API 与服务端校验

保留 `DELETE /api/projects/{project_id}`，请求体扩展为项目名称确认和销毁确认文字。服务端按以下顺序检查：

1. 当前用户是否为技术管理员；
2. 项目是否存在；
3. 请求中的项目名称是否与当前项目名称完全一致；
4. 请求中的销毁确认文字是否严格为“永久删除”；
5. 项目是否仍可被锁定和删除。

删除前状态仅用于审计；不再作为拒绝条件。删除成功后保留一条不含业务快照的 `delete_project` 审计日志，记录操作者、项目 ID、项目名称及删除前状态。

## 数据与文件清理

删除覆盖显式以项目或其子对象关联的业务数据，包括：

- 项目成员、成员变更申请、重点工作、关键任务草稿和执行事件；
- 更新提交、问题、项目通知、项目结束申请；
- 会议、会议文档、会议转录/修订、会议评审、变更集、会议和启动 AI 运行记录；
- 项目成果、成果提交、成果附件；
- 项目立项附件和立项 AI 分析运行记录；
- 其它受外键约束且直接属于该项目的数据。

服务端先枚举附件和会议文档，且只接受可安全解析到受控上传根目录内的文件路径。删除采用两阶段处理：

1. 将已验证的文件移动至同一受控存储卷上的项目专属待销毁目录；
2. 在一个数据库事务中按外键依赖顺序删除业务数据与项目主记录，并写入审计日志；
3. 数据库提交成功后，物理删除待销毁目录中的文件。

数据库提交前失败时，回滚数据库并将已移动文件恢复原位置。数据库提交后若物理删除失败，项目数据保持不可访问，系统记录待清理文件和失败原因，并提供幂等、安全的重试清理机制；重试只能处理该项目待销毁目录中的文件，不能遍历或删除其它路径。

## 错误处理

- 非技术管理员：403。
- 项目不存在：404。
- 两项确认内容任一不匹配：422。
- 删除期间项目被其它操作占用、已被删除或发生并发冲突：409。
- 数据库或存储异常：在尚未提交时回滚并返回安全错误；提交后文件待清理时明确返回删除已完成但清理待重试的状态，不泄露文件路径。

## 测试与验收

后端测试覆盖：

- 技术管理员删除每一种生命周期状态的项目；
- 非技术管理员被拒绝；
- 项目名称或“永久删除”确认文字不正确时不删除；
- 数据库关联数据按依赖顺序清理；
- 附件仅在安全路径内被暂存/删除；
- 提交前异常会回滚记录并恢复文件；
- 提交后物理清理失败能留下可重试的待销毁项。

前端测试覆盖：

- 入口仅对技术管理员显示，且不受项目状态限制；
- 双重确认不完整时无法提交；
- 成功后项目列表与缓存更新；
- 403、404、409、422、网络错误和待清理状态都能明确呈现。

本地端到端验收仅新建专用测试项目，不对现有项目执行删除，除非操作者在功能完成后另行指定并再次确认。
