# 驾驶舱待完善项目刷新设计

## 目标

当负责人进入驾驶舱时，刷新其项目列表，使新下发的多个待完善项目同时显示在“待完善立项”清单中，无需手动刷新浏览器。

## 根因

后端项目列表已经返回负责人参与的两个 `dispatched` 项目，驾驶舱也会遍历所有符合条件的项目。问题来自 `ProjectContext` 只在登录或应用首次加载时请求项目列表；项目在当前浏览器会话中被下发后，内存中的 `projects` 仍是旧值。

## 方案

`DashboardPage` 挂载时调用现有的 `reloadProjects`，从 `GET /api/projects` 同步最新项目集合。已有的 `fillableProjects` 过滤和映射保持不变，因此返回的每个负责人项目都会参与数量统计和行渲染。

不加入定时轮询、WebSocket 或后端接口变更；刷新失败时保留已有项目列表，避免干扰驾驶舱当前内容。

## 回归测试

新增前端结构/行为测试，覆盖：

1. `DashboardPage` 从项目上下文取得并在挂载时调用 `reloadProjects`。
2. 待完善清单基于所有 `dispatched` / `returned` 且角色为 `owner` 的项目渲染，不进行单条截断。

## 范围

仅修改驾驶舱加载项目列表的前端逻辑与测试；不改项目状态、后端权限、接口契约或其他页面的数据刷新策略。
