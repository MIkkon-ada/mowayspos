# 项目下发待定结束日期与草稿可见性设计

## 目标

允许项目在未填写结束日期时下发；草稿项目在下发前只对公司 CEO / 管理员可见，项目负责人及其他项目成员均不可通过项目列表、登录上下文或项目入口看到该项目。

## 决策

### 项目下发

项目下发保留项目目标和开始日期校验。结束日期改为可选：为空时不进行格式或先后顺序校验；填写时仍须为 `YYYY-MM-DD`，且不得早于开始日期。成功下发后状态仍为 `dispatched`，并仅通知严格意义上的项目负责人。

### 草稿可见性

项目成员的普通可见项目集合只包含非草稿项目。公司 CEO / 技术管理员的全量管理视图保持可见草稿，以便继续配置和下发。

同一规则必须应用于两个后端投影：

- `GET /api/projects` 的项目列表；
- 登录/刷新会话使用的 `/api/auth/me` 项目引用列表。

因此前端无需依赖隐藏或过滤来维持权限边界；即使直接调用 API，负责人也不能取得草稿项目。

## 错误处理

- 缺失项目目标或开始日期：仍返回现有的下发校验错误。
- 提供的结束日期格式非法或早于开始日期：仍返回现有的精确错误。
- 草稿项目的负责人登录或刷新会话：得到不含该项目的空项目集合（除非其另有已下发项目）。

## 回归测试

新增后端测试覆盖：

1. 结束日期为空的草稿项目可以下发并通知负责人。
2. 填写非法或早于开始日期的结束日期仍不能下发。
3. 草稿项目对负责人不出现在 `GET /api/projects`，但对 CEO 仍可见。
4. 草稿项目对负责人不出现在 `/api/auth/me` 的项目引用中，但对 CEO 仍可见。

## 范围

仅调整项目下发校验、项目列表和登录上下文的后端查询与测试；不改数据库字段、不新增状态，也不改现有的项目表单交互。
