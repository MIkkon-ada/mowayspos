# 项目初始化导入规范化设计

## 目标

让工作推进表导入能正确保留仅有的开始日期，并在应用已确认的 AI 草稿时安全补齐人员与项目成员关系。

## 范围

- 将仅含年月的计划时间规范为该月第一天的开始日期；结束日期保持为空。
- 保留完整日期作为开始日期，不伪造结束日期。
- 以 Excel 的单行记录生成来源证据，避免所有候选都显示整张工作表。
- 由 AI 将“专项”作为重点工作，将“关键任务”仅作为其子任务；父级描述使用成果或完成标准，不能重复第一项关键任务。
- 应用草稿时，已有组织人员但不在项目中时自动添加为项目普通成员。
- 组织人员库中没有的具体人名自动创建为无登录账号的普通成员，并加入当前项目。
- 不自动创建部门、岗位/角色、泛化称谓或账号标识；这些内容仍保持未匹配并供人工补充。

## 数据流

Excel 解析器输出带行号的行级文本块。AI 生成阶段将计划时间归一化为 `plan_start` 与可选的空 `plan_end`。预览仍显示原始姓名和警告。用户选择应用草稿后，后端以事务方式解析可创建的姓名：先查询或创建组织人员，再确保存在当前项目的 `member` 关系，最后将生成的人员 ID 写入关键任务负责人/协助人。

## 安全与错误处理

人员自动创建只接受经过规范化后的、非空且不含组织/角色关键词的具体姓名；重复姓名按规范化名称复用已有在职人员。若创建或成员关系写入失败，整个应用操作回滚，不产生部分任务或部分人员。不会自动创建登录账号、授予项目负责人权限或修改其他项目。

## 验收

- `2026-06` 在预览与写入中变为 `plan_start=2026-06-01`、空结束日期。
- 一行 Excel 任务的 evidence 仅引用该行的坐标和文本。
- 具体未匹配姓名在应用后可作为本项目成员被绑定；“咨询部”“各项目经理”“mowasyadmin”不被自动建为人。
- 首个关键任务不再同时作为父级描述显示。
