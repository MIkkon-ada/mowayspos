# 关键任务下新增任务计划设计

## 目标

让关键任务执行工作台中“任务计划”空状态的“添加计划”成为真实操作入口。新增记录直接归属当前关键任务，不创建新的关键任务层级。

## 范围

- 在有管理计划权限且关键任务未完成时显示可点击的“添加计划”按钮。
- 点击后打开新增任务计划抽屉，填写计划事项、预期成果、负责人、协助人、计划时间、完成定义及可选说明。
- 默认负责人使用当前关键任务负责人；默认状态为“未开始”。
- 保存时调用既有 `POST /api/subtasks/{subtask_id}/monthly-plans` 接口。
- 保存成功后关闭抽屉并刷新工作台，因此计划列表、汇总统计和推进记录同步更新。
- 无权限时不展示新增入口；已完成的关键任务不允许新增，仍由后端提供保护性校验。

## 交互与数据

工作台现有的关键任务 ID 作为 `subtask_id` 传给既有月度计划接口；该接口创建的 `ExecutionSchedule` 记录即是当前页面展示的任务计划。表单使用该接口已要求的字段，不新增数据库、DTO 或第二套计划数据。

负责人初始值取当前关键任务负责人。协助人可为空。标题和预期成果为必填；时间和完成定义允许按现有接口规则选填。提交失败时抽屉保持打开并显示接口返回的错误，不刷新页面数据。

## 组件边界

- `ExecutionPlanTable` 只负责按权限展示按钮，并把点击事件上报给工作台。
- `KeyTaskExecutionWorkspace` 管理新增抽屉的打开、保存和刷新。
- 新增计划抽屉负责表单校验和调用既有客户端 API。

## 验收与测试

- 空计划状态在可管理时渲染真实按钮；不可管理时不渲染入口。
- 点击按钮打开新增计划表单，默认负责人为关键任务负责人。
- 提交有效信息调用当前关键任务的新增计划接口，成功后刷新并关闭抽屉。
- 客户端单元测试、现有结构测试和前端生产构建均通过。
