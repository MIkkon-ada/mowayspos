# CVM Nginx 入口启动修复设计

## 背景

发布 `c348aaa` 到 CVM 后，后端和数据库迁移均已健康，但前端容器卡在
Nginx 官方入口目录中的 `10-listen-on-ipv6-by-default.sh`。该脚本调用
`apk manifest nginx`，未进入 Nginx 主进程，导致前端健康检查无法通过。

## 方案

在生产阶段镜像中仅删除 `10-listen-on-ipv6-by-default.sh`。继续使用官方
`/docker-entrypoint.sh` 和其余入口脚本，保持已有的 Nginx 配置、静态文件、
反向代理、端口及健康检查不变。

## 边界与错误处理

- 不固定或降级 Nginx 基础镜像，不绕过安全更新。
- 不替换完整入口程序，避免丢失官方初始化行为。
- 不修改数据库、Compose 网络、宿主 Nginx、DNS 或 TLS。
- 镜像构建和容器启动验证失败时不发布、不切换 CVM。

## 验证

先添加回归测试，要求 Dockerfile 明确移除该脚本；测试应先在当前版本失败。
修复后运行生产部署契约测试、前端构建、镜像构建、Nginx 配置校验，以及本地
容器对根路径和代理健康接口的验证。仅在这些检查通过后发布不可变镜像并在 CVM
重建前端容器，最后验证容器健康和循环地址的页面、健康 API、未认证边界。
