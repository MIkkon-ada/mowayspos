# 项目立项工作推进表导入与自动成员纳入设计

## 目标

修复“填写项目方案 → AI 从文件生成”对工作推进表 Excel 的导入：对可识别的工作推进表走确定性、可追溯的行级转换，不因单元格内换行或合并单元格退回大模型；使用全组织启用人员完成精确姓名识别；在负责人正式提交项目方案时，将已识别但尚未加入项目的人员自动纳入项目并绑定到任务。

## 范围与边界

- 适用于项目立项分析中的 `.xlsx`、`.xls` 工作推进表。
- AI 分析和“应用草稿”始终只修改浏览器内草稿，不创建项目成员、任务或其他正式数据。
- 只有既有“提交立项审核”请求会写入项目成员与任务，且在一个数据库事务中完成。
- 非 Excel 文档、结构无法识别的表格和角色描述继续允许 AI 提供草稿，但必须标为待确认。
- 本次不修改项目权限模型，不自动创建组织人员，也不回写历史分析运行。

## 目标数据流

```text
上传附件
  → 创建冻结分析快照（项目成员 + 全部启用组织人员）
  → 解析 Excel 为逐行、可追溯来源块
  → 识别到工作推进表时确定性转换；否则调用受控 AI 草稿
  → 草稿显示人员匹配与“提交时自动加入”状态
  → 应用草稿（仅前端本地状态）
  → 提交立项审核（事务内补齐 project_members，再写任务绑定）
```

## Excel 确定性导入

### 识别条件

来源文件为 Excel，且行块的表头包含“重点工作”（或既有同义表头）与“关键任务”（或既有同义表头）。不要求“目标”列可用。

### 行块读取

解析器生成的行块格式为“表头 + 一个换行符 + 制表符分隔的数据行”。数据单元格可包含换行符。因此结构化转换必须只以第一个换行符分开表头和数据行，不能对整个块使用 `splitlines()` 后取第二行。

每行保持文件名、工作表和精确单元格范围作为证据。对于合并的“重点工作”“统筹人”等列，继续使用同工作表前一个非空值作为该行上下文，直到出现新的非空值。

### 字段映射

| Excel 列 | 草稿字段 |
| --- | --- |
| 重点工作 | 重点工作标题 |
| 评价标准 | 重点工作描述；同时作为关键任务验收标准的后备值 |
| 关键任务 | 关键任务标题 |
| 责任人 | 关键任务负责人/协助人 |
| 协同人 | 关键任务协助人 |
| 计划开始时间 | `plan_start` |
| 计划结束时间 | `plan_end` |
| 完成情况 | `status`（仅保留原文，不推断枚举状态） |
| 备注、问题与协调 | 关键任务描述 |

ISO 日期直接规范为日期；只有明确年月的值才按现有规则转换为月初日期。类似“持续（3场以上）”不得当作结束日期。

## 人员识别与成员纳入

### 冻结候选集

创建分析运行时，快照保存两份人员信息：当前项目成员，以及所有启用的组织人员。分析可以向项目负责人展示组织人员姓名，仅用于姓名精确匹配；不向模型提供账号凭据或联系方式。

姓名以去除首尾空白和大小写归一化后匹配唯一启用人员：

- 已是项目成员：写入人员 ID，状态为 `project_member`。
- 仅是组织人员：写入人员 ID，状态为 `will_join_project`；界面说明“提交时自动加入项目”。
- 同名、停用、未找到：不写入人员 ID，保留原始文本并显示待确认。
- “项目经理”“全员”“无”等角色或群体描述：不推断为某个人，不创建组织人员。

### 多人责任人

“责任人”单元格按 `、`、中文或英文逗号、分号和斜杠拆分。第一个可识别的人为关键任务负责人，其余可识别的人与“协同人”列中的人员合并为协助人，去重后保留。角色或群体描述仍保留为待确认文本，不伪造人员绑定。

例如“吴肖、郭熠彬”生成负责人“吴肖”、协助人“郭熠彬”；两人若均为启用组织人员，则都在正式提交时自动加入项目。

### 正式提交

沿用现有负责人提交事务：在写入重点工作和关键任务前，收集草稿中所有有效人员 ID；对非项目成员创建 `project_members` 行，角色为 `member`，已存在成员不重复创建；随后写入任务负责人和协助人绑定。任一人员校验或任务写入失败，事务完整回滚。

## 界面行为

- 已在项目的人员显示正常已绑定状态。
- 组织中已匹配但尚未入项目的人员显示“提交时自动加入项目”，不再显示“未匹配人员”。
- 真正未识别的姓名、角色描述和多人值中不可识别的片段显示黄色待确认说明。
- “应用草稿”不改变项目成员；提交成功后刷新项目成员与任务数据。

## 错误处理与审计

- 未识别人员阻止正式提交的现有规则保持不变。
- 运行快照保持不可变；已有运行不会因目录或成员变化而改变结果，修复后由用户重新分析。
- 自动新增的项目成员使用既有成员同步审计记录，审计中记录人员 ID、项目 ID 与来源为负责人提交；不记录附件正文或提示词。

## 验收

1. 使用含合并“重点工作”单元格和含换行单元格的真实工作推进表，确定性导入不调用聊天模型。
2. 所有明确任务行、开始/结束日期、责任人和协同人均与源表对应，证据定位到各自行范围。
3. 杨宇帆、邹奇敏等已存在组织目录但未在 `test1` 项目中的人员，分析时显示“提交时自动加入项目”。
4. “吴肖、郭熠彬”转换为吴肖负责人、郭熠彬协助人；两人提交后均为项目成员。
5. “项目经理”“全员”等不会创建成员或错误绑定，且仍要求人工确认。
6. 应用草稿后取消或关闭页面不会改变数据库；正式提交成功后才新增项目成员和任务。
7. 任一提交阶段错误会回滚本次创建的项目成员和任务写入。
