# 负责人提交方案页布局设计

## 目标

将负责人提交项目方案页收敛为已确认的 B 方案：左侧固定展示项目概览，右侧使用“重点工作列表 + 当前重点工作详情”的双栏结构，减少与当前任务无关的文案和统计信息。

## 交互与展示约束

- 顶部保留项目标题、状态、说明和“返回项目详情”；返回按钮默认显示浅色背景。
- 左侧标题使用“项目概览”，不折叠，统一展示项目编号、名称、状态、周期、项目目标/完成准则、背景、补充说明、项目说明和项目角色。
- 左侧不展示项目类型、客户名称、预期交付物，也不展示“基础信息由管理层维护”等辅助说明。
- 右侧标题只保留“工作推进方案”、AI 按钮和“+ 新增重点工作”，移除解释性副标题。
- 右侧重点工作采用 B 方案：左栏仅列重点工作题目，右栏展示当前重点工作；当前详情标题使用编号 + 题目，不再出现“重点工作 01”。
- 当前详情保留目标成果、计划时间、关键任务表和“+ 新增关键任务”。关键任务表列为：关键任务、负责人、协助人、时间段、评价指标、操作。
- 移除重点工作行中的关键任务数量、底部“继续新增重点工作”按钮，以及因收起/展开分支造成的两套重点工作 JSX。展开状态由同一份重点工作数据驱动。
- 保留现有保存、删除、人员选择、时间段编辑、AI 草稿和提交审核逻辑。

## 数据边界

本次不改变 Project 或提交接口字段。现有 `project.expected_outcomes` 仍以“补充说明”展示，重点工作的 `task.description` 仍以“目标成果”展示；关键任务的 `evaluation_standard` 仍作为“评价指标”编辑和提交。

## 验证

- 新增组件级回归测试，确认字段/按钮文案和 B 方案结构存在，确认不需要的文案不存在。
- 执行前端单元测试和 TypeScript/Vite 构建。
- 在本地负责人提交页检查宽窄屏：左侧项目概览不折叠，右侧工作列表与详情不溢出，固定底部操作栏仍可用。
