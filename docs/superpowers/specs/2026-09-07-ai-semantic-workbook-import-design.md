# AI 语义工作簿导入设计

## 目标

让项目立项的 Excel 导入依赖单元格语义和表格结构，而不是依赖固定表头文本。对于表头变体、合并单元格和单元格内多行任务，系统应完整保留目标、验收标准、推进流程、关键任务及其来源位置。

## 范围

- 项目立项“AI 从文件生成”入口中的 `.xlsx`、`.xls` 工作簿。
- 保留现有上传校验、分析快照、AI 草稿预览、人员匹配和正式提交事务。
- 增加目标成果、验收标准、推进流程的结构化传递和展示。
- 不修改已有分析运行记录；修复后由用户重新分析。

## 设计原则

1. Excel 解析器只负责完整读取工作簿结构、单元格原文、合并关系和来源坐标，不因未知表头而丢弃数据。
2. AI 负责语义识别和层级归纳。`主要工作`、`重点工作`、`工作模块`等表头都可以映射为父任务；目标、成果、验收标准和推进流程分别映射到对应字段。
3. 后端负责安全边界：字段长度、日期格式、人员 ID、证据来源和草稿 schema 必须校验；不得由 AI 发明人员、日期或来源。
4. 如果原始字段有内容而草稿字段为空，系统应执行字段补全或明确标记待确认，不得静默丢失。
5. 未知列保留在来源证据或扩展字段中，不能因为无法映射就删除。

## 数据结构

AI 内部标准结构包含：

- 父任务：`title`、`goal`、`acceptance_criteria`、`process`、人员、时间、证据。
- 子任务：`title`、`description`、`evaluation_standard`、人员、时间、证据。

对现有接口保持兼容：旧客户端仍可使用 `description` 和 `evaluation_standard`。新字段随草稿、预览和负责人提交接口传递；正式任务保存时分别写入目标成果、完成标准和推进流程字段。

## 数据流

```text
上传 Excel
  → 读取结构化工作簿与原始单元格
  → AI 识别列语义、父子层级和多行任务
  → 服务端校验并补全缺失字段
  → 预览目标成果、验收标准、推进流程和关键任务
  → 用户应用到负责人表单
  → 正式提交时事务写入任务及子任务
```

AI 输出必须为严格 JSON，并为父任务、子任务及每个重要字段保留可验证的文件名和单元格范围。补全失败时要在预览中显示警告，不得将有来源内容的字段无提示地写为空。

## 界面

每个重点工作展示：

- 目标成果：可编辑文本。
- 验收标准/关键成果：可编辑文本。
- 推进流程：放在目标成果之后，可编辑并保存。
- 关键任务列表：保留负责人、协助人、时间和评价指标。

## 测试与验收

- 使用当前 `第三阶段五项工作的简要方案_v0.2.xlsx`，五个父任务、目标、验收标准、推进流程和所有明确编号任务均可追溯。
- 使用同一内容但替换为“工作模块”“目标成果”“实施步骤”等表头，结果保持一致。
- 合并父任务单元格和单元格内多行关键任务不会丢失或串行。
- 原始字段有值时，最终草稿不能无提示地输出空值。
- AI 返回缺字段、非法证据或非法人员 ID 时，系统给出可审核错误并阻止静默写入。
- 现有项目立项、人员绑定和提交事务测试继续通过。
