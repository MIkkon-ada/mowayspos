# 项目初始化 AI 草稿服务模块边界设计

## 目标

在不改变项目初始化 AI 的外部导入路径、草稿字段、模型调用策略或审核流程的前提下，将当前混合协议、归一化、表格解析和调用编排的超大服务拆分为可独立理解与测试的内部模块。

## 当前事实与约束

- `app.services.project_init_ai_agent` 约 1,871 行；现有路由、分析 worker、视觉分析服务和测试都直接从该模块导入类型或函数。
- 该模块已经承载严格的来源证据、人员匹配、重复任务识别、结构化表格快速路径、模型 JSON 解析和多批次合并逻辑。拆分不得放松这些校验，也不得改变模型调用次数或回退条件。
- 项目初始化 AI 的近期功能修复均已通过全量测试；本轮是边界治理，不扩展业务功能或数据库 schema。

## 方案比较

1. 保持单文件：没有短期迁移成本，但继续让协议和复杂算法互相耦合，后续变更风险最高。
2. 一次性重写为新包并替换所有导入：结构最整齐，但公开与私有测试导入面很广，难以定位回归。
3. 保留兼容外观层，按职责渐进拆分：外部仍从 `project_init_ai_agent` 导入；新模块只承接内部实现，每一步都由既有行为测试和新增导入兼容测试保护。

采用方案 3。

## 模块边界

### 兼容外观：`project_init_ai_agent.py`

保留全部既有公共符号，以及当前测试和内部服务实际导入的辅助符号。文件只负责重导出和把 `generate_project_init_draft()` 委托给调用管道；不再包含协议定义、表格解析或草稿归一化算法。

### 协议：`project_init_ai_contracts.py`

负责 Pydantic 草稿模型、受限常量、错误类型和安全验证诊断。它只依赖 Pydantic、标准库和 `SourceChunk` 的类型定义，不依赖模型调用或持久化。

### 归一化：`project_init_ai_normalization.py`

负责人员候选解析、来源索引、证据限定、任务/子任务/项目档案合并、重复分类和 `normalize_agent_result()`。输入与输出均使用协议模块中的类型，不执行模型调用。

### 结构化表格：`project_init_ai_spreadsheet.py`

负责工作表范围解析、表头规范化、行投影和确定性草稿快速路径。它只调用归一化层来生成最终草稿，不解析模型回复。

### 调用管道：`project_init_ai_pipeline.py`

负责批次切分、提示词构造、受限 JSON 解析、模型调用、证据修复、多批次合并和确定性表格回退。它依赖前述三个内部模块；不访问数据库，不写入项目、任务或成员。

## 兼容与错误处理

- `project_init_ai_agent` 仍是唯一兼容入口，因此现有调用方和测试无需变更导入路径。
- 原来的中文安全错误消息、`ProjectInitAiError` 类型层次、`ProjectInitAiResult` 字段、结构化表格回退条件以及脱敏诊断代码必须保持一致。
- 禁止在外观层引入循环导入；各内部模块只能向下依赖协议层，调用管道可依赖所有下层模块。

## 验证

每个拆分任务先用导入兼容测试固定旧模块符号与行为，再以现有 `test_project_init_ai_agent.py`、`test_project_init_analysis.py`、`test_ai_capability_integration.py` 覆盖正常、回退与失败路径。最终运行完整后端、前端测试和构建；对比模型调用次数与结构化表格快速路径的断言不变。

## 不在范围内

- 不修改模型、数据库迁移、路由 URL、权限规则或前端交互。
- 不重新设计提示词、超时、模型优先级或 Excel 业务字段。
- 不删除历史兼容导入；其移除只能在调用方完成迁移且有单独设计后进行。
