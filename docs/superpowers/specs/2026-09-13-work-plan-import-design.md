# 工作计划表导入设计

## 背景

项目管理当前的批量导入只识别简化表头，并且每一行只创建 `Task`。系统真实的工作计划表包含“重点工作”和“关键任务”两层，导入后没有创建 `SubTask`，所以数据不能完整出现在工作推进表中。

## 目标

让用户可以把系统导出的完整工作计划表复制到“项目管理 → 批量导入”中，预览并确认后，得到可直接使用的三层数据：项目 → 重点工作 → 关键任务。

## 范围与约束

- 保留当前复制粘贴方式，不在本轮引入文件上传和新的存储服务。
- 同时兼容现有简化格式和完整工作计划表格式。
- 不修改现有项目、任务和关键任务的业务语义：`Task` 代表重点工作，`SubTask` 代表关键任务。
- 导入使用事务：存在校验错误时不写入任何业务数据。
- 重复导入按“项目 + 重点工作 + 关键任务”判断，已有记录跳过并在结果中提示。

## 设计

### 前端解析

把解析逻辑从页面组件抽到独立模块。模块先定位包含“关键任务”或“重点工作”的表头行，再规范化表头别名；因此可识别系统导出表的合并标题行 + 表头行结构。标题行形如“项目名称目标与重点工作计划表”时提取项目名称作为项目名。对 Excel 合并单元格复制产生的空白项目名和重点工作名执行向下继承。

完整格式映射如下：

| 工作计划表字段 | 导入字段 |
| --- | --- |
| 目标 | project_objective |
| 项目 / 阶段 | project_name |
| 重点工作 | workstream |
| 评价标准 / 完成标准 | completion_standard |
| 关键任务 | key_task |
| 责任人 / 负责人 | owner |
| 计划开始时间 | plan_start |
| 计划结束时间 | plan_end |
| 计划时间 | plan_time |
| 协同人 / 协同 / 成员 | collaborators |
| 完成情况 / 当前状态 / 状态 | status |
| 备注 / 问题 | notes |

没有“重点工作”列的旧格式继续把“关键任务”列作为重点工作名称，并创建一个同名关键任务，以保持旧数据可导入。完整格式没有项目列时必须从标题行取得项目名；标题行无法识别项目名时，该批次阻断并提示用户补充项目列或使用标准模板。

### 后端落库

扩展批量导入行结构，保留旧字段并增加 `workstream`、`plan_start`、`plan_end`、`notes`、`project_objective`。导入流程按项目名称缓存项目；按重点工作名称缓存 `Task`；每个有效关键任务创建一个 `SubTask`。

- `Task.key_task` 保存重点工作名称。
- `Task.completion_standard` 保存重点工作的评价标准。
- `SubTask.title` 保存关键任务名称。
- `SubTask.assignee`、`plan_time`、`status` 保存关键任务责任人、计划时间和状态。
- `SubTask.notes` 保存协同人和备注，协同人以 `协同人：...` 开头，保证计划表能显示。
- 项目目标写入新项目的 `objectives`；已有项目不覆盖已有目标。
- 同一项目下同名重点工作复用；同一重点工作下同名关键任务跳过。

整个导入过程在单个事务中完成，校验失败执行回滚。

### 预览与用户反馈

导入弹窗先展示解析行数、重点工作数、关键任务数、待跳过重复数和错误行。错误包含缺少项目名、重点工作或关键任务。确认按钮只在存在有效行且没有阻断错误时启用。导入完成后显示实际创建和跳过数量，并刷新项目列表及推进表数据。

## 验收标准

1. 复制系统导出的完整工作计划表，前端解析出有效行，不再显示“未识别到有效数据”。
2. 合并单元格导致的空白项目名和重点工作名能被正确继承。
3. 导入后数据库中同时存在 `Task` 和对应的 `SubTask`，层级关系正确。
4. 工作推进表能显示重点工作、关键任务、责任人、计划时间、协同人和备注。
5. 缺少必要字段时不产生部分数据。
6. 重复导入不会重复创建相同的重点工作和关键任务。
7. 旧的简化批量导入格式和既有测试继续通过。
