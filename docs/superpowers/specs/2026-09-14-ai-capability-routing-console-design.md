# AI 能力路由台重设计

## 目标

将系统设置中的 AI 能力配置改造成一个可直接判断系统健康度和调用链路的路由工作台，参考“AI能力路由台-重设计.html”的信息架构和视觉语言，同时继续使用现有模型、凭据、能力策略和连接测试接口。

## 现状问题

- 模型卡片和能力策略上下堆叠，无法快速看出哪个模型被哪些能力使用。
- 主模型、备用模型和异常状态分散在每个能力的小区域内，降级关系不直观。
- 页面宽度受通用设置页面限制，无法承载模型池与路由主区的并排布局。
- 当前保存接口已经支持主模型、备用模型和超时配置，但前端交互没有形成统一的路由编辑体验。

## 设计

### 页面骨架

AI 设置区使用宽屏工作台：

1. 顶部标题“AI 能力路由台”，副标题解释优先模型和自动降级规则；
2. 四个健康度指标卡：模块就绪度、模型连接健康、主用负载最高、语音能力缺口；
3. 主体两列：左侧模型资源池，右侧能力路由主区；
4. 顶部视角切换：按模块·降级链路 / 按模型·资源负载。

### 数据映射

- 模型状态由现有 `enabled` 和 `credential_configured` 计算：停用、缺少 API Key、已配置。
- 能力状态由当前策略链路和首个模型状态计算：待配置、主用异常、就绪、就绪·备用异常。
- 资源池显示每个模型被多少能力引用、被多少能力作为主用。
- 模块视图显示主模型 → 备用模型链路，并保留异常提示。
- 模型视图显示每个模型覆盖的能力、主用能力和备用能力。

### 交互

- “接入新模型”继续打开现有 `AIModelDrawer`，真实创建模型并刷新资源池。
- 每个能力的“编辑链路”打开右侧路由抽屉，支持上移、下移、移除和添加符合类型的启用模型。
- 抽屉保存继续调用 `saveAICapabilityPolicy`，保存主模型、备用模型、超时和最大尝试次数。
- 模型卡片继续支持编辑、连接测试、启用/停用。
- 加载失败、保存失败、连接测试结果沿用现有错误提示机制，并在工作台内显示。

## 视觉方向

采用参考页面的“克制的运营控制台”风格：浅灰蓝背景、白色面板、细边框、低强度阴影；靛蓝表示主用链路，青绿色表示语音和健康状态，琥珀色表示风险，红色表示不可用。路由链路使用带角色标签的节点和箭头，减少文字堆叠。

## 兼容与边界

- 不修改 AI 配置 API、数据库结构、模型抽屉表单和权限控制。
- 不改变能力默认列表和保存协议。
- 非 AI 设置页面继续使用原来的窄版设置布局；只有 AI 能力配置使用宽屏容器。
- 小屏幕下主体列自动变为单列，路由节点允许换行，抽屉保持全宽可用。

## 验证

- React 测试验证能力列表、健康度、路由视图切换、路由保存和模型类型过滤。
- 结构测试验证 AI 路由台的核心文案和真实 API 调用仍存在。
- TypeScript 构建验证组件类型和生产打包。
