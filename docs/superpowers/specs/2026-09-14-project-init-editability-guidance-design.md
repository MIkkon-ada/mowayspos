# 项目立项编辑权限与状态提示设计

## 目标

让项目立项页面在用户操作前就明确说明“谁可以完善工作推进表”和“当前项目是否允许编辑”，避免上传文件后才出现英文的 `project lifecycle is not editable`。

## 现状与根因

- 后端项目立项附件与分析接口只允许 `dispatched`（已派发）和 `returned`（已退回）状态写入。
- 项目负责人页面的状态徽章目前固定显示“待负责人完善”，没有读取项目真实状态。
- AI 面板按钮没有根据项目生命周期禁用，导致不可编辑项目也能发起上传，最终由后端返回 409。
- 审核中的项目应保持只读，不能通过前端绕过审核流程继续修改。

## 设计

### 1. 统一状态来源

复用前端已有的项目生命周期解析函数，`dispatched` 和 `returned` 才被视为可编辑；其他状态均为只读。页面标题和项目概览使用真实状态标签，不再硬编码“待负责人完善”。

### 2. 编辑态与只读态

- 可编辑状态：负责人可以编辑重点工作、关键任务、人员、时间、AI 草稿和提交审核。
- 不可编辑状态：保留项目概览和工作推进方案内容用于查看；右侧编辑控件、AI 导入、新增/删除和提交按钮全部禁用。
- `pending_review` 显示“项目已提交审核，当前只能查看，需审核退回后才能继续完善。”
- 其他不可编辑状态显示当前状态和“需进入已派发或已退回状态后才能编辑”的说明。

### 3. 权限边界

项目负责人入口权限继续由现有 `project.owner_submit` 规则控制；本次只补强页面自身的生命周期兜底。后端现有生命周期校验保留，防止绕过前端直接调用接口。

### 4. 错误处理

前端在打开工作台时根据真实状态给出提示并提前禁用操作，不再让用户先上传后看到英文接口错误。接口仍然返回原有安全错误，便于审计和其他客户端正确处理。

## 验收标准

1. `dispatched` 和 `returned` 项目显示可编辑状态，AI 面板和提交按钮可用。
2. `pending_review` 项目显示“待审核”、只读说明，AI 面板与所有编辑写操作不可用。
3. `draft`、`active`、`ended`、`archived` 等项目不再出现可点击的 AI 分析入口。
4. 现有负责人提交成功流程不变。
5. 后端生命周期校验与现有测试继续通过。
