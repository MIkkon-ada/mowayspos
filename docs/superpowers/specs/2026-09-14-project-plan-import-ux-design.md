# 项目工作计划导入体验设计

## 目标

把项目管理中的 AI 工作计划导入从“宽表格编辑器”改为简洁、直观的两阶段工作台：先提供来源并选择归属，再查看分组结果、按需修正，最后确认写入。

## 用户体验原则

- 首屏只解决“从哪里导入”和“导入到哪里”，不提前展示空的结果表。
- 识别完成后优先展示项目、重点工作、关键任务三个数量和需要注意的警告。
- 结果按重点工作分组，关键任务默认只显示名称、负责人、时间和状态；备注、来源、验收标准等低频字段按需展开。
- 不使用横向滚动的大表格，不用渐变和过度强调“AI”；保留现有设置页的白底、浅灰边框、蓝色主操作。
- 任何时候都明确“尚未写入”，确认按钮只在可导入且用户处于复核阶段时启用。

## 交互结构

### 阶段一：提供内容

顶部显示标题、简短说明和关闭按钮。主体只有一个来源卡片：上传文件与粘贴表格两个入口，使用轻量切换按钮；文件名或粘贴状态显示在卡片内。项目归属使用一行“已有项目 / 新项目名称”控件，避免单独占用一个大区域。主按钮为“开始分析”。

### 阶段二：复核并导入

分析成功后替换主体内容。顶部显示“已识别”或“规则降级”状态、来源文件和三项数量。警告以一条可读提示呈现。下面按重点工作显示分组卡片；每个分组包含目标摘要和关键任务列表。每个关键任务默认呈现核心字段，点击“编辑”才展开字段输入。项目名称在复核区顶部可直接修正。

底部固定操作栏：左侧显示“确认后才会写入项目数据”，右侧提供“返回修改来源”和“确认导入 N 条”。分析中、导入中禁止关闭和重复提交。

## 技术边界

- 复用现有 `previewAiProjectPlan`、`applyAiProjectPlan` 和 `draftToBatchImportRows`，不改变 API 和数据库行为。
- 新增纯函数负责把 `BatchImportRow[]` 按项目与重点工作分组，供组件和测试使用。
- 仅修改 `ProjectPlanAiImportDialog.tsx`、分组辅助模块、组件/契约测试；项目管理入口保持现有权限和刷新逻辑。
- 真实账号只用于部署后的人工验收，不写入源码、测试夹具或日志。

## 验收标准

1. 上传和粘贴入口清晰可见，项目归属在同一行完成。
2. 分析后不再出现 `min-w-[980px]` 的横向宽表格。
3. 结果按重点工作分组，关键任务支持按需展开编辑。
4. AI、规则降级、警告、三项数量和“确认后才写入”状态均可见。
5. 预览/确认接口调用行为不变，已有导入转换测试继续通过。
6. 前端单元测试、契约测试和生产构建通过。
