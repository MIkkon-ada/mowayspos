# 项目立项工作推进表导入工作台设计

## 目标

将现有“项目管理 → 批量导入”流程替换为项目立项阶段的“项目概览 + AI 任务树”审核工作台。用户上传工作推进表或项目方案后，先查看项目概览，再按重点工作逐项核对、编辑、查看来源并采纳，全部确认后才写入项目数据。

## 设计

- 顶部：项目立项标题、AI/规则识别状态、整体采纳进度和关闭/返回操作。
- 左侧：项目概览，包括项目名称、目标、背景、预期交付物、计划周期、导入文档和识别统计。
- 右侧：工作推进方案任务树，按重点工作分卡片展示目标成果、验收标准、计划时间和关键任务。
- 任务操作：支持编辑任务、负责人、状态、计划日期和备注；支持按重点工作采纳；支持一键全部采纳。
- 来源追溯：从任务或重点工作打开来源抽屉，展示原文件、定位信息和 AI 提取证据摘要。
- 降级提示：规则提取时显示“AI 当前不可用，已自动切换为规则提取，请重点核对关键字段”。
- 底部：确认进度、未写入提示和确认导入按钮；未全部采纳或关键字段为空时禁止确认。

## 技术边界

- 复用 `previewAiProjectPlan`、`draftToBatchImportRows` 和 `applyAiProjectPlan`，不改变数据库写入接口。
- 通过现有 `BatchImportRow[]` 保存用户编辑，确保预览和最终入库使用同一份数据。
- 使用现有 AI evidence 数据实现来源抽屉；没有证据时不显示虚假的来源定位。
- 现有“＋新建项目”基础表单和项目权限边界保持不变；替换的是工作计划导入工作台。

## 验收标准

1. 进入导入流程后不再显示旧的窄弹窗式结果表，而是显示概览 + 任务树工作台。
2. AI 识别和规则降级状态、项目概览、任务数量、待指派数量和确认进度可见。
3. 重点工作和关键任务可以编辑、逐项采纳、批量采纳。
4. 任务来源可以打开抽屉查看文件名、位置和证据摘要。
5. 只有全部重点工作已采纳且关键字段完整时才能确认导入。
6. 原有预览/确认接口、权限和刷新行为保持不变。
