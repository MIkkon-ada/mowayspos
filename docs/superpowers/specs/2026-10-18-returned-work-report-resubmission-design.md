# 退回工作汇报重新提取与核对设计

## 背景与目标

当前退回汇报在 `VoiceUpdateDetailDrawer` 中直接编辑原始文字并调用 `/api/confirmations/{id}/resubmit`。这个请求没有传入新的 `human_result`，后端因此保留原 `ai_result_json` 和 `human_result_json`；负责人收到的汇报文字可能已修改，任务进展卡片却仍来自旧内容。

目标是让提交人修改退回汇报后，重新运行提取、核对结构化结果，再将同一条汇报重新送回负责人审核。提取失败或核对未完成时，不得重新提交，也不得让旧结构化结果冒充新结果。

## 方案选择

1. **复用工作汇报的提取与核对工作台（选定）**：退回详情提供“修改并重新提取”入口，带着原汇报 ID 和修订文字进入现有工作汇报流程。提交人重新提取并编辑结果后，最终操作更新原汇报 ID。这样可以复用已有卡片、归属选择和校验行为，改动范围集中。
2. **在详情抽屉内重做完整编辑器**：直接把提取、卡片编辑、任务归属和提交都塞进抽屉。工作量和重复逻辑较多，也会让窄抽屉承载复杂任务卡编辑，不采用。
3. **只清除旧卡片并提交文字**：可避免旧卡片混淆，但负责人看不到新内容对应的结构化进展，未满足“重新提取、核对再重提”的要求，不采用。

## 交互与状态流

从退回汇报详情进入“修改并重新提取”后，在现有工作汇报工作台打开该汇报的修订模式：

1. 将原汇报文字载入输入区，允许提交人修改；展示退回原因及“正在修订原汇报”的提示。
2. 提交人明确点击“重新提取”后调用现有仅提取接口。提取只生成候选结果，不写入正式汇报记录。
3. 提取成功后进入现有结果核对界面，提交人可以修正摘要、进展卡、任务归属及问题卡，并通过原有必填校验。
4. 最终按钮显示“核对无误，重新提交”。操作调用退回汇报的 resubmit 接口，并同时传入原汇报 ID、修订文字、完整核对后的 `human_result` 及补充说明；不得调用创建单条/批量汇报的接口。
5. 成功后保持同一汇报 ID，状态回到待负责人审核，刷新历史和审核待办。

退出修订模式时，已输入但尚未提交的文字保存在工作汇报本地草稿机制中，按现有用户与项目隔离规则存储。重新打开修订模式时恢复该草稿；成功提交后清理该修订草稿。

## 数据与接口行为

- 重新提取仍调用 `POST /api/updates/extract`，使用原汇报所属项目/任务上下文和修订后的全文，不写入正式汇报或新任务。
- 最终重提仍调用 `POST /api/confirmations/{id}/resubmit`，必须携带非空、完整的核对后 `human_result`。后端更新原记录的文字和人工核对结果，再转回待负责人审核。
- 后端审计日志应保留原记录快照，并记录修订全文、补充说明和新提交的结构化结果；不创建新的汇报记录。
- 重提期间禁用重复操作。服务端失败时保留修订文字和核对结果，留在修订模式并显示错误，允许重试。
- AI 提取失败时保留修订文字，显示失败原因和重试入口；不进入结果核对页，不调用 resubmit。上一次退回记录中的 AI/人工卡片不得被当作本次提取结果。
- 新建任务建议或子任务草稿不能因重提而创建第二份正式草稿；修订模式沿用当前审核边界，只有审核流程原有的明确动作可以产生后续业务数据。

## 权限与边界

继续由后端验证当前用户是原提交人、汇报仍处于退回状态且有权写入。修订不改变项目成员权限、负责人审核流程、项目/任务归属或退回理由。复用的提取接口必须按原汇报上下文做相同的项目访问校验。过期或已经被处理的退回记录在 resubmit 时由后端拒绝，前端保留输入并提示刷新状态。

本次只处理工作汇报退回后的修订和重新提交，不改项目立项、会议纪要或其他确认事项。

## 最少验证与验收

遵循用户“尽可能减少测试”的偏好，只增加覆盖关键风险的少量验证：

- 一个前端流程验证：从退回报告进入修订工作台，修改文本，重新提取并编辑结果，最终向原 ID 发送核对后的 `human_result`，且不调用 create/batch 接口。
- 一个失败路径验证：提取失败时保留修订文本、继续处于输入阶段，并且 resubmit 未被调用；resubmit 服务端失败时修订内容仍可重试。
- 一个后端接口验证：必须使用提交的新文字和结构化结果更新同一条退回记录、状态回到待负责人审核、审计日志保留前后信息；缺少核对结果不得重提。
- 构建前端，并运行上述定向验证。模型服务不可用时，记录提取的真实服务验证为未完成，不以 mock 验证代替。

人工验收：对一条退回汇报修改文字后重新提取，核对卡片，再提交；在负责人审核入口看到同一汇报的新文字和新卡片。另验证制造提取失败后内容仍在，不能提交旧卡片。

## 未包含内容

不改写 AI 提取质量、不增加模型供应商配置、不调整项目或任务权限、不重做整套工作汇报视觉、不在抽屉内复制完整卡片编辑器，也不新增平行的汇报记录。
