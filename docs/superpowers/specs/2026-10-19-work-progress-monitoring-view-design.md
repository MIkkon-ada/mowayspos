# 工作推进表项目监控视图改进设计

**状态：** 待用户审阅  
**范围：** 验收项 C02–C05；保留工作推进表作为主要页面，不另建重复的驾驶舱。

## 目标

让管理者打开一个项目的工作推进表后，能够快速回答：总共有多少关键任务、完成多少、延期多少、还有多少未解决问题；问题任务在哪里；每项工作的最新已确认进展和下一步是什么。用户可以直接从概览进入对应明细，并能在窄屏下继续查看任务。

## 现状与问题

V2 的 `TaskManagementPage` 已有项目指标、搜索、快捷筛选和分组折叠；`PlanTableViewV2` 已有重点工作分组、最新已确认进展列、下一步列及风险/延期标记。主要缺口是这些功能尚无本轮用户视角验收证据；指标、分组摘要和结果明细的口径尚需用同一组样例核对；桌面与移动端的主要信息完整性未验证。当前本地 6005 和 8011 均无监听进程，因此不能将静态代码检查当作页面验收。

## 设计

### 1. 项目概览与指标口径（C02）

- 概览固定在工作推进表上方，保留五项：关键任务总数、已完成、延期、待确认日期、未解决问题。
- 所有任务指标以当前授权项目、当前项目筛选和完整关键任务集合计算；明确指标单位为“项关键任务”。问题指标单位为“条未解决问题”，两种单位不混用。
- 延期按系统现有延期规则计算，完成任务不因过去计划日期计入延期；未解决问题严格按问题状态计算，风险标记不冒充问题数量。
- 点击指标应用相应筛选并在页面显示当前条件；未解决问题指标只筛选存在未关闭问题的任务，不能把问题条数当任务数。
- 问题数据加载中、为空和加载失败分别展示；失败时显示“暂不可用”，禁止显示为 0。失败状态下禁用问题指标和问题筛选。

### 2. 重点工作分组与折叠（C03）

- 计划表按“重点工作”分组，每组标题显示名称、关键任务完成数、延期任务数、风险任务数及未解决问题任务数。
- 组内行仍是关键任务，保留责任人、计划时间、状态、最新进展、下一步及现有详情入口。
- 折叠仅隐藏组内行，不改变数据、过滤结果、统计口径或导出内容；筛选后只保留命中任务所在的重点工作分组。
- 长重点工作标题允许换行或完整查看，不以省略号作为唯一可读方式。展开状态使用项目 SVG `ChevronDownIcon`。

### 3. 主要视区与进展信息（C04）

- 桌面默认视图在不横向滚动的主要区域内优先呈现关键任务、负责人、时间、状态、最新已确认进展摘要和下一步；可选字段不得挤占这些默认字段。
- 最新进展与下一步分列展示，进展显示来源和确认时间；未确认汇报只显示待确认状态提示，不泄漏为正式进展。
- 长文本提供可访问的全文查看方式；不依赖鼠标悬停作为唯一入口。
- 390×844 下使用既有移动端任务卡片路径；任务名、状态、延期/风险、责任人和最近进展可读且操作可触达。

### 4. 常驻搜索与快捷筛选（C05）

- 搜索框和快捷筛选保持在概览区；搜索覆盖重点工作、关键任务和责任人。
- 快捷条件包括全部、延期、待确认日期、有风险、关联未解决问题；需要组合的负责人和精确状态沿用筛选面板。
- 当前生效条件需可见并可逐项清除；一键重置恢复完整当前项目结果。
- 结果行、命中数量、分组统计与导出使用同一筛选条件。风险条件按风险标记筛选；问题条件按未关闭问题关联筛选。

## 数据流与边界

沿用现有项目授权、任务、子任务和问题读取接口；不新增数据库表、字段或权限。使用页面已有任务/子任务数据计算任务口径指标；问题数量和关联通过当前项目问题数据计算。若来源请求失败，保留错误状态，不把错误转换为空数据。未确认汇报继续与正式进展分离。

保留项目选择、字段显示配置、列宽、计划表层级、任务详情入口和 Excel 导出。工作推进表仍是核心工作界面；本次不创建独立驾驶舱，不更改工作汇报确认流程或项目生命周期。

## 实施边界与验收

- 涉及文件以 `frontend-v2/src/pages/TaskManagementPage.tsx`、`frontend-v2/src/components/task-management/PlanTableViewV2.tsx`、`planTableViewModel.ts`、`workProgressWorkspace.css` 及对应组件测试为主；仅在现有数据接口不足时才扩展 API。
- 使用一组包含未开始、进行中、已完成、延期、有风险、未解决问题和已关闭问题的隔离样例，人工复算总数并逐一点击指标/筛选核对结果。
- 只新增或调整覆盖口径与筛选交互的定向自动化检查；视觉验收记录桌面 1366×768、1440×900 与移动 390×844 的真实页面截图。运行一次 V2 构建确认类型与样式可打包。
- C02–C05 只有在真实页面、数字与明细、交互、移动展示均有证据后才标记通过。构建成功或已有组件代码不能代替这些证据。

## 主要风险

- 统计可能混淆关键任务数、重点工作数和问题条数；UI 标签与筛选必须注明单位。
- 不同接口加载时机可能造成概览暂时不一致；指标在相关数据完整前显示加载状态，不先显示 0。
- 当前本地开发服务未启动；需要先检查安全配置并用隔离数据启动本地验收，不能直接拿项目主数据库做破坏性样例。
