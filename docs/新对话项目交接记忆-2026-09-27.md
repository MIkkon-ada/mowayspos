项目：MOWAYS 项目管理系统，后续界面修改以 `frontend-v2` 为准。

## 使用说明

开始新对话时先读本文和仓库根目录的 `AGENTS.md`。本文记录用户已明确表达的长期偏好和相关页面背景，供新任务理解上下文；新任务的具体范围仍以用户当轮指令为准。不要把未完成的建议当作已经确认的需求。

## 用户与产品背景

- 用户是开发人员；系统供公司老板、PM 和项目成员共同使用，三类人使用频率相近。
- 工作围绕项目展开；每个人通常优先完成自己负责项目中的工作。
- 老板主要掌握全局并统一调度，不应把老板首页设计成个人执行任务入口。
- 应根据现有代码识别用户参与的项目和角色，不要先假定所有人都需要相同的工作视角。
- 用户希望直接、认真地修正实际页面，不要只给建议或擅自缩小已明确的修改范围。

## 界面与交互偏好

- 使用 `frontend-v2`，不要误改旧版前端来实现 V2 页面需求。
- 页面信息应在常见桌面视口内清晰可读；工作推进表不要让用户被迫横向滚动才能查看关键信息。
- 控件和信息层级应克制、清楚，避免不必要的标题重复、重复入口、空字段和占据注意力的工具栏。
- 所有下拉、展开/收起等方向箭头必须来自项目图标库的 SVG 图标组件，优先复用 `ChevronDownIcon`。禁止 Unicode 字符或文本字形箭头。
- 项目导航里不要添加无实际作用的“项目工作区”选择器；“我的项目”如果只是再次打开同一张工作推进表，就属于重复入口。用户曾要求清除无必要的项目工作区关联。

## 工作推进表已确认的信息结构

业务数据层级固定为三层：**项目 → 重点工作 → 关键任务**。

- 项目有具体项目名称和项目总体标准；总体标准类似项目目标/验收口径，不应误作重点工作或任务字段。
- 一项重点工作下可有多个关键任务。重点工作应以跨行/分组的方式表达所属关系；不要在每条关键任务前重复写一遍重点工作名称。
- 不需要单独的“交付成果”列。
- “验收标准”放在每个重点工作下方，以可点击入口呈现；点击后再打开详情界面，不要把整段标准铺满表格。
- “最新进展”和“下一步计划”是两个独立字段/列，不要合并成一个字段。
- WBS 编号不需要显示。
- 项目总体标准位于表格最左侧区域，可折叠/展开；展开控件与项目名称在同一行。项目名称在顶部居中，可切换项目；标题只显示项目名称，不再重复“项目工作推进表”。
- 筛选入口放在页面中，但展开结果应是紧凑的小浮层/小面板；筛选项不应包含项目选择，因为顶部项目名已经负责切换项目。
- “导出 Excel”和“新增重点工作”收纳在“操作”菜单中；移除原先为这两个按钮单独占用的额外工具栏行。
- “在办/回收站”切换控件已明确要求隐藏。

## AI 模型名称显示：本轮修改

用户要求语音/工作汇报页面的“提取模型”显示具体配置模型名称，不能再显示类似“AI能力策略（ ）”的空括号。

本轮已修改：

- 后端 `bowei_ai_dashboard/app/routers/ai_config.py` 增加已登录可读的只读接口，读取 `task.extraction` 的主模型名和备用模型名；只返回模型标识，不返回密钥、地址或连接配置。
- V2 API 封装位于 `frontend-v2/src/api/aiConfig.ts`。
- `frontend-v2/src/pages/VoiceUpdatePage.tsx` 加载配置，并在“提取模型”选项中显示主模型和备用模型。缺少配置时显示“未配置模型”；接口不可用时显示“模型信息暂不可用”，不留空括号。
- 本地配置核查时看到主模型 `deepseek-flash`、备用模型 `qwen-plus`。这是当时本地数据库里的值，换环境/数据库后以接口实际返回为准。
- 验证已执行：V2 `npm run build` 成功，后端路由 Python 语法编译成功；没有运行测试套件。
